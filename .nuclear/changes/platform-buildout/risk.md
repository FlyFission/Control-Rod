# Risk: controlled platform buildout

- **Mode:** Standard
- Standard-plus routing: changes persisted requirements, runtime boundaries and eventual release subjects.
- Execution owner: Codex under the user's 2026-10-23 instruction to specify, plan and execute the recommended sequence.
- Decision owner: repository owner; no protected-surface signature or contributor certification inferred.
- Mission: make engineering requests reproducible, reviewable and traceable from capture through accepted evidence.

| Risk | Control | Stop condition |
|---|---|---|
| Proposal stack confused with main | Isolated branch pinned to both; preserve original commits | Main merge before owner/DCO gates |
| Duplicate JSON keys or partial runner records | Validate raw profile and generated boundary contracts before use | Invalid job starts an agent |
| Preparation bypasses release | Explicit enrollment, CAS snapshots, release closed until signed manifest exists | Enrolled work uses legacy release |
| Stale requirements accepted | Immutable revisions, subject digests and atomic validation | Old subject mutates current basis |
| Prompt-only runtime restrictions | Manual preparation first; actual confinement before agent enablement | Agent access granted without enforcement proof |
| Product scope claimed ahead of evidence | Per-task status and tests; future gates named | Planned capability described as implemented |

Protected kernel decisions, policies, CI, red-team fixtures and major spec versions require the signature in AGENTS.md. Existing contributors must supply their own DCO certifications. No deployment or public release is authorized by this record.
