## Review fixes (Codex blind check of PR #164)

Fixed on `claude/project-thread-2ozsln` after the Codex blind check; findings and lines are in the review note `pr164-pr165-codex-findings.md`.

- P1 egress: a ChatGPT-signed-in Codex reaches `chatgpt.com` and `auth.openai.com`, which are not model endpoints in `models.json`. `harnessSignInHosts` in `daemon/internal/runner/daemon.go` adds them to the Codex author allowlist only. Test: `TestAuthorEgressHostsAllowCodexChatGPTSignIn`, and the Codex case of `TestWireAuthorEgressFilterPoliciesAndCheckerSkip`.
- P2 lock order: `dismissCapture` now locks the intake runs before the capture, the same order as the intake claim.
- P2 completion events: savepoints are refused by the command executor, so `recordRunEvents` refuses an `events_from` that is itself out of range, or whose last origin would not fit the int column, before it writes anything. The refused-completion path rethrows any non-refusal error instead of writing into an aborted transaction. Test: "refuses an events_from whose origins would overflow" in `services/api/test/run-events.test.ts`, including an empty batch at one past the int range.
- P2 shutdown: `pnpm cr start` keeps both children in the terminal's process group, so a launcher crash or a closed terminal still reaches them. A Ctrl+C reaches the daemon directly and starts its own graceful stop; the control plane, started with `CONTROLROD_LAUNCHER_STOPS_API=1`, ignores SIGINT and is stopped with SIGTERM by the launcher only after the daemon has exited, so the daemon's final completions still reach it. The launcher waits for the daemon with no fixed cap (the daemon bounds its own grace, stop ladder and drain). Its signal and exit handlers are installed before the health wait, so a Ctrl+C or a failed start during startup stops the control plane and never starts the daemon. A second Ctrl+C stops both at once. If the control plane exits unexpectedly, the launcher still stops the daemon first, and completions the daemon cannot deliver stay in its outbox for the next start. A SIGKILL of the launcher alone leaves both children running, as before this change.
- P3: `apps/web/e2e/phase3-exit.spec.ts` uses `.places-group-toggle`, opens every collapsed group, and loads the page again before the first Tab. A local Chromium run still fails that test, because on load focus is already on the active place, so the first Tab reaches the next place rather than the skip link. That is app behaviour, recorded as a follow-up, not caused here. The 320 px reflow test also fails here and on main; the control-room change (#165) fixes it.

Local results for these fixes: daemon `go vet` and `go test ./...` pass apart from the bubblewrap checker tests (no `bwrap` on the test machine); API suite 897 passed, 2 failed (SEC-01 and SEC-03, the trust-authentication environment issue in `docs/status.md`); web typecheck and Vitest 823 passed.
