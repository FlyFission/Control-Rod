1. **High: [docs/superpowers/specs/2026-11-06-review-panel-design.md:68](/home/flyfission/worktrees/control-rod-panel/docs/superpowers/specs/2026-11-06-review-panel-design.md:68)** specifies Codex `-s read-only`, which sets `sandbox_mode`. ADR 0021 says that setting causes Codex to ignore the permission profile that denies access to login files and other sensitive paths. The proposed profile can therefore bypass the intended confinement. Remove `-s read-only`, define a compatible read-only permission profile, and qualify that exact invocation with credential-read and write-denial tests.

2. **High: [docs/superpowers/specs/2026-11-06-review-panel-design.md:70](/home/flyfission/worktrees/control-rod-panel/docs/superpowers/specs/2026-11-06-review-panel-design.md:70)** says Codex and Claude Code are qualified without stating the limits. The existing evidence covers specific versions on WSL2, and the full ADR 0021 qualification suite remains unfinished. This can lead R1 to enable seats without the required platform and tool-path evidence. State the exact versions, platform, and remaining gaps, and gate each reviewer configuration on its own qualification.

3. **High: [docs/superpowers/specs/2026-11-06-review-panel-design.md:55](/home/flyfission/worktrees/control-rod-panel/docs/superpowers/specs/2026-11-06-review-panel-design.md:55)** claims that selecting tracked files means a stray `.env` is never sent. A `.env` file or another secret can be tracked, and reviewers can read the snapshot itself, not only the brief. The design can therefore disclose credentials to a provider despite its stated protection. Apply an explicit content-selection and secret-handling policy to the snapshot and diff before upload or provider access, and test tracked secrets as well as untracked files.

4. **Medium: [docs/superpowers/specs/2026-11-06-review-panel-design.md:80](/home/flyfission/worktrees/control-rod-panel/docs/superpowers/specs/2026-11-06-review-panel-design.md:80)** requires every finding to anchor to a path and lines in the head snapshot, although the schema also permits section-only locations and branch reviews can concern deleted files or deleted lines. Valid findings about removals or document sections would be quarantined as unverifiable. Define location types and deterministic checks for sections and for both sides of a diff, with tests for deleted files and lines.

5. **Medium: [docs/superpowers/specs/2026-11-06-review-panel-design.md:86](/home/flyfission/worktrees/control-rod-panel/docs/superpowers/specs/2026-11-06-review-panel-design.md:86)** equates falling below the requested quorum with a single consultant and no cross-vendor check. If quorum is three and two different vendors answer, that statement is false; conversely, two seats from one vendor do not establish cross-vendor review even if a seat-count quorum is met. Compute quorum status and cross-vendor participation separately, and report the actual counts.

6. **Medium: [docs/superpowers/specs/2026-11-06-review-panel-design.md:90](/home/flyfission/worktrees/control-rod-panel/docs/superpowers/specs/2026-11-06-review-panel-design.md:90)** does not explain how a run with the new `review` role becomes an existing pre-check. The current completion path invokes `finishPreCheck` only for `pre-check` runs and rejects unsupported completion roles; it also records a pre-check outcome and applies baseline and runtime checks. A developer following the design cannot submit a review seat through that path as written. Specify whether the designated seat is created as a pre-check run or how its result is converted, including outcome, baseline, revision binding, and independence checks.
