REVISE

1. **High: [review panel design:64](/home/flyfission/worktrees/control-rod-panel/docs/superpowers/specs/2026-11-06-review-panel-design.md:64)** applies the secret policy to the head snapshot and diff, but [line 98](/home/flyfission/worktrees/control-rod-panel/docs/superpowers/specs/2026-11-06-review-panel-design.md:98) also requires retaining the base tree. A secret removed from a file can remain elsewhere in that base file, outside the diff, and reach storage or a reviewer without being scanned. The earlier tracked-secret finding is therefore only partly resolved. Apply the policy before upload to every retained or readable base artifact as well, and test a secret in an unchanged portion of a base file.

2. **High: [review panel design:68](/home/flyfission/worktrees/control-rod-panel/docs/superpowers/specs/2026-11-06-review-panel-design.md:68)** binds non-interactive confirmation to the digest of the exclusion and findings list, rather than to the content being sent. Files can change while that list stays the same, allowing an earlier confirmation to authorize different content. Bind confirmation to the post-policy snapshot, base and diff digests, the policy result, lane, and recipients; reject it if any change.

3. **Medium: [basis.md:33](/home/flyfission/worktrees/control-rod-panel/.nuclear/changes/review-panel/basis.md:33)** still says Codex and Claude Code pass the ADR 0021 qualification suite today. The revised design correctly limits existing evidence to author launches on WSL2 and says the full suite remains open. This contradictory assumption can mislead a developer deciding whether to enable a reviewer seat. Replace it with the exact evidence limits and the per-invocation qualification gate.

4. **Medium: [review panel design:114](/home/flyfission/worktrees/control-rod-panel/docs/superpowers/specs/2026-11-06-review-panel-design.md:114)** now creates the designated seat as a pre-check, but does not reconcile that design with the existing queue and job construction. `queueRun` can return an already active pre-check, and the claim path selects an independent runtime rather than the requested seat. The existing pre-check job also includes package context and deliverables beyond the panel snapshot. Consequently, the linked run may use a different provider or input set than the person confirmed. Specify how the request binds the run, runtime, reviewer profile and approved inputs, including the existing-run case, and test those bindings.

5. **Medium: [review panel design:114](/home/flyfission/worktrees/control-rod-panel/docs/superpowers/specs/2026-11-06-review-panel-design.md:114)** counts the pre-check seat when its outcome is `ok`, although the same paragraph requires its pre-check outcome to be `pass`, `fail`, or `inconclusive`. Without a separate mapping between run completion status, panel seat outcome, and verification outcome, an implementer cannot reliably count that seat or handle a successful pre-check that reports a failure. Define and test the mapping independently of the verification verdict.
