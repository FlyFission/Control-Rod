1. **Critical — `docs/superpowers/specs/2026-11-16-role-casting-design.md` (`## 7. Capital Projects mode role catalog`), `.nuclear/changes/role-casting/risk.md` (`R-04`)**
   - **Quote:** `Findings; an **alternate calculation** by an independently selected method where the grade requires it | Independent reasoning; choosing a different method; spotting unit and boundary errors`
   - **What is wrong:** `Calculation checker` explicitly instructs the model to choose an engineering method (`choosing a different method`), directly contradicting Section 7 (`No engineering method, tolerance or standard is chosen by this spec.`), `R-04` (`methods, tolerances and references from a qualified domain owner`), and Section 14 (`Capital Projects roles drift into choosing methods or tolerances`). It also assigns tool-driven generation (`an alternate calculation`) to a role whose duty is `Check` rather than `Generate through a tool`.
   - **Fix:** Require the alternate calculation's method (and tolerances) to be supplied or selected by a qualified domain owner from approved method definitions—never chosen by the model—and split or explicitly type the alternate-calculation execution as a `Generate through a tool` step separate from `Check`.

2. **Critical — `docs/superpowers/specs/2026-11-16-role-casting-design.md` (`## 5. Duties`, `## 7. Capital Projects mode role catalog`, `## 9. Role trials: how a cast is earned`)**
   - **Quote:** ``Writes: `CalculationRun` input record and method script; results come from the run``; `Parametric model or drawing script for a pinned CAD tool`
   - **What is wrong:** Checking only that output numbers trace to a tool run (`every number in the output traces to a tool run`) ignores input numbers. Writing a `CalculationRun` input deck, `method script`, or parametric CAD script requires geometry dimensions, loads, safety factors, tolerances, boundary conditions, and solver/mesh parameters; letting the model write numeric literals into those inputs violates AGENTS rule 5 ("no engineering number is typed by a model").
   - **Fix:** Require generated scripts and input records to bind numeric engineering inputs symbolically by ID from controlled `DesignBasisItem`, `InterfaceRecord`, or owner-supplied method templates, paired with a deterministic check rejecting un-sourced numeric literals in model-authored inputs/scripts.

3. **Critical — `docs/superpowers/specs/2026-11-16-role-casting-design.md` (`## 8. The casting sheet`, `## 11. Fit with the kernel and the existing gates`)**
   - **Quote:** `At claim time the control plane walks the candidates in order and takes the first that passes, in this order: admission (lane, harness qualification for this platform and version, pin), provider separation against the author and other seats, capability tier for the grade, budget and quota.`; `The sheet's min_tier must be at or above the grade floor; the kernel checks the floor.`
   - **What is wrong:** Four kernel/enforcement gaps weaken separation, tier floors, and quorum:
     1. **Safety quorum:** Taking `"the first that passes"` does not specify how Safety's 2-of-2 quorum from different families is selected from a single ordered candidate list, nor how inter-seat family separation is enforced when walking candidates.
     2. **Tier spoofing and `effort`:** Section 11 implies the kernel checks `sheet.min_tier` rather than looking up the candidate's `(harness, model, effort)` tier in the signed registry (unlike `separation`, where Section 8 explicitly notes `"the kernel reads the signed policy, not this field"`). Moreover, if registry tiers are not keyed by `effort`, a sheet can pass the tier floor with a top-tier model paired with minimal/low `effort`.
     3. **Quota/budget fallback:** Walking to lower-ranked candidates on `budget and quota` lets transient quota/budget pressure silently downgrade a cast (e.g., to a weaker model or lower `effort`).
     4. **Local models on Safety/Material:** Section 2 states `"local models never deciding on Safety or Material"`, but Section 8 only enforces lane restrictions on local candidates, leaving Safety/Material `Refuter`, `Test author`, or `Extract` roles unguarded against local-model casting.
   - **Fix:** Have the kernel read capability tier directly from the signed registry keyed by `(harness, model, effort)` (removing `min_tier` as an enforceable sheet field); define multi-seat selection for 2-of-2 quorum enforcing distinct families across all selected seats; forbid budget/quota fallback to lower-ranked candidates on `Check`/`Refute` (hold the run instead); and enforce the Safety/Material local-model ban across all deciding/checking duties in the kernel.

4. **Critical — `docs/superpowers/specs/2026-11-16-role-casting-design.md` (`## 10. Composition without subagents`, `## 13. Milestones`), `docs/adr/0023-role-casting.md` (`## Conditions`), `.nuclear/changes/role-casting/trace.md` (`RC-3`)**
   - **Quote:** `Separation rules apply across the whole flow instance: a checker node must be separate from every originator node it judges.`; `A run cast with model X that reports model Y is refused as a check.`
   - **What is wrong:**
     1. **Consult/upstream taint:** A `consult` node attaches its output to an asking run's next round, and `Extract`, `Plan`, and `Test author` nodes shape deliverables or acceptance criteria. Limiting flow-wide separation to `"every originator node"` allows a `consult`, `Extract`, or `Plan` node to run on the same vendor/family as the downstream checker, reintroducing shared blind spots.
     2. **Asymmetric `observed_models` enforcement:** Refusing mismatched `observed_models` only `"as a check"` (ADR 0023, `RC-3`, C3) leaves an `Originate`, `Test author`, or `Consult` run that silently ran model Y (or a subagent) able to pass, breaking downstream provider separation when the checker only separates from cast model X.
     3. **Unenforced C5 window:** Milestone C5 casts and runs `refuter` in sheet version one before C6 adds kernel enforcement of `"refuter separate from raiser"` and flow-wide separation.
   - **Fix:** Extend flow-wide separation so checkers are separate from all upstream contributing nodes (`Originate`, `Generate through a tool`, `Test author`, `Consult`, `Extract`, `Plan`) whose outputs feed the checked deliverable; reject *any* run (author, consult, or check) whose `observed_models` diverges from its single cast model; and move C6's kernel separation rules ahead of C5 (or exclude `refuter` and multi-node flows from C5 until C6 lands).

5. **Major — `docs/superpowers/specs/2026-11-16-role-casting-design.md` (`## 2. What this reopens, and what it keeps`, `## 8. The casting sheet`, `## 9. Role trials`, `## 15. Open owner decisions`)**
   - **Quote:** `The multi-provider plan (non-goals) cut "an editable strengths matrix, and any learning loop", and chose a static ordered list of eligible checkers.`; `From live work the control plane already records (or plans): first-pass acceptance (UsageRecord), sticky fails, finding dispositions (accepted, rejected with reason), model mismatches, quota hits.    - **What is wrong:**
     1. **Strengths matrix & learning loop by another name:** A `(role, grade, lane) -> ordered (harness, model, effort, trial_ref)` table driven by role trials and live `first-pass acceptance` / `finding dispositions` reports is functionally a strengths matrix and a human-in-the-loop learning loop, differing from the cut design primarily in requiring a passkey signature between iterations.
     2. **Checker shopping vectors:** Using live `first-pass acceptance`, `sticky fails`, and `rejected` finding dispositions as signals to recast checkers (including agent-drafted recasting proposals), allowing `trial_ref: none` owner-judgement overrides (`C-5`), allowing `Check` trials to penalize `findings on clean items` without weighing missed real defects, and walking down the sheet on `budget and quota` all create pathways to demote strict checkers in favor of compliant ones.    - **Fix:** Remove `first-pass acceptance` and `finding dispositions` from recasting triggers for `Check`/`Refute` roles (keep production signals strictly to operational health: `model mismatches`, `quota hits`, crash/timeout rates); forbid `trial_ref: none` for `Check`/`Refute` duties (or require passing the canary suite first); forbid agent-drafted sheet proposals for checker roles; and explicitly retire or subordinate `RuntimePin` to the signed sheet in C2.

6. **Major — `docs/superpowers/specs/2026-11-16-role-casting-design.md` (`## 9. Role trials: how a cast is earned`), `.nuclear/changes/role-casting/basis.md` (`## Assumptions and invalidation triggers`), `docs/adr/0023-role-casting.md` (`## Decision`), `.nuclear/changes/role-casting/trace.md` (`RC-4`)**
   - **Quote:** `Trial scores can be produced by scripts alone for every duty except plan quality, where an owner edit distance is recorded by the owner.`; `Seeded defects found (anchored, through review panel Stage 1)`; `Correct upheld or refuted, with a citation that passes Stage 1.`; `Claims not in the source (checked against a fact list).`; `Packages with hidden acceptance tests, drawn from merged work in this repository and frozen at a commit.`; `Each set is rotated when a new candidate is added.`
   - **What is wrong:**
     1. **Non-scriptable `Plan` scoring:** `owner edit distance, recorded by the owner` contradicts ADR 0023 (`scored only by scripts`) and `RC-4` (`Score reproduced by rerunning the scoring script on stored outputs`), cannot be reproduced by re-running a script, and does not scale to rotated trial sets or blinded evaluation. (Checking whether criteria in a new plan `"map to a test or a check"` is likewise either trivial syntax checking or requires semantic judgement.)
     2. **Semantic gap in script-only claims for `Check`, `Refute`, `Summarize`, `Extract`:** Determining whether a free-text finding actually describes a seeded defect (rather than an unrelated comment near the same line), whether a cited line actually refutes a finding, whether free-text summary claims entail only facts in a fact list, or whether extracted prose matches an answer key cannot be done reliably by deterministic scripts without either brittle formatting / easily gamed line-overlap heuristics or an LLM judge (which `basis.md` flags as an invalidation trigger and Rule 5 forbids).
     3. **Missing `Summarize` completeness metric:** Measuring only `Claims not in the source` lets a model emit a single trivial true sentence to score 100%.
     4. **Contamination & invalid cross-version comparison in `Originate`:** Drawing tasks from `"merged work in this repository"` risks training-data contamination for any public/indexed repo history. Additionally, rotating a trial set `"when a new candidate is added"` invalidates comparisons against previously tested candidates whose stored `trial_ref` ran on an older `trial_set_digest` unless all active candidates are re-run on the new set.
   - **Fix:** Replace `Plan` owner-edit-distance scoring with a deterministic downstream harness (or remove `Plan` from scripted trial gating and label it owner judgement); constrain `Check`/`Refute`/`Extract` trial outputs to structured defect/verdict/locator schemas matched against explicit predicate checks (or explicitly bound what scripts verify vs. blind human grading); add a fact-coverage recall measure to `Summarize`; source `Originate` trials from private/unmerged tasks rather than merged repository commits; and require all compared candidates in a sheet proposal to share the same `trial_set_digest`.
