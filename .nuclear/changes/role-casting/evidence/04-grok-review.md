VERDICT: FLAWED AS WRITTEN

1. **Critical.** `docs/superpowers/specs/2026-11-16-role-casting-design.md` section 2, and `docs/adr/0023-role-casting.md` (Amends, Decision 3). Quote: "It is the static ordered list the plan already chose, extended from checkers to every role." The plan's cut, quoted in the same section, is "an editable strengths matrix, and any learning loop", replaced by a static checker list. This sheet is that matrix: ordered candidates per role, grade and lane, filled from comparative trials. Recasting is the loop. Section 9 says production signals, including sticky fails and finding dispositions, are "a reason to run a trial or propose a new sheet", and "An agent may draft the proposal". Section 3 says "Casting picks, per role, the candidate that did best" and "the model is what trials choose." The Check score counts "findings on clean items", so a quieter checker ranks better. C-5 allows `trial_ref: none`. Risk R-01's stop condition allows any change that carries a new signature, and the plan's static list was already signed. A signature does not distinguish this from the thing that was cut. The ADR line "Amends" that non-goal contradicts section 2's claim that the cut is kept. Fix: keep one signed, static eligible list for checkers, with no trial-ranked reorder and no agent-drafted proposal. If the owner wants role-level model choice for authors only, say that C-1's proposed answer is no for checkers, and delete "did best" and "trials choose".

2. **Critical.** Spec section 7, Calculation checker, against section 3 principle 3 and the section 7 close. Quote: "Independent reasoning; choosing a different method" and "an alternate calculation by an independently selected method where the grade requires it." That role chooses the method. The same section says "No engineering method, tolerance or standard is chosen by this spec", and principle 3 says tools make the numbers. DN-05, cited as the prerequisite, says an approved input supplies the tolerance and the model does not invent it. The duty is Check, whose rule is "never fixes the work", on the checker profile "read-only, scratch output". An alternate calculation either types results, which breaks AGENTS rule 5, or gives the checker a tool-writing sandbox, which breaks checker confinement. Fix: the qualified domain owner selects the alternate method and the approved tool. The checker compares the recorded run with that owner-supplied run. Delete "choosing a different method" from the model's job.

3. **Major.** Spec sections 5, 8 and 11. Quote: "takes the first that passes, in this order: admission (lane, harness qualification for this platform and version, pin), provider separation against the author and other seats, capability tier for the grade, budget and quota." One winner cannot fill the Safety 2-of-2 quorum that section 2 says is unchanged. The Check rule is only "Different vendor and family from the originator"; the plan's pairwise rule between checkers is absent, and the refuter rule drops family ("A vendor different from the raising seat"). The walk also omits the accepted ban, quoted in section 2, that local models never decide Safety or Material. `grade` and `lane` may be `any`, and the match order is undefined, so an `any` row can become the Safety cast. "The sheet's `min_tier` must be at or above the grade floor" lets the sheet declare the floor. The kernel has to use the signed registry tier of the observed model and ignore `min_tier`. The review panel this spec builds on binds confirmed seat recipients, and its claim path deliberately ignores the seat the panel requested. Replacing that with the sheet's first candidate sends the snapshot to a provider the person did not confirm. Fix: state seat filling, pairwise family, the local-model ban, and specific-grade-before-`any` as kernel rules. Keep confirmed review seats as the recipients. Make a missing or quota Safety seat inconclusive.

4. **Major.** Spec section 10, against ADR 0020 as cited in the pattern note. Quote: "attaches its output to the asking run's next round as a frozen, untrusted input." ADR 0020, which section 2 and the pattern note keep, is one headless print-mode run that exits. A next round inside the asking run is mid-run continuation, which the plan cut. The consult target is not under the separation sentence that follows ("a checker node must be separate from every originator node it judges"), so a same-family specialist can write the analysis the checker adopts. Nothing says the specialist is fixed by a signed flow rather than chosen by the asking agent. Fix: a consult is a new print-mode run, queued only from a signed flow, with its own cast. Apply vendor and family separation to every consult that a checker reads, and end the asking run before that input exists.

5. **Major.** Spec section 8, "Version zero", against section 11 and the sheet fields. Quote: "author by today's `pickRuntime` order (claude, codex, fake) ... pre-check by today's `pickChecker` order (codex, claude, fake) with today's owner-override rule". The harness field is "claude, codex, grok, agy, opencode, local" and has no `fake`, so the last step of both orders cannot be encoded. I read `pickRuntime` and `pickChecker` in `services/api/src/work.ts`: those orders and the override match the verification note. The same claim path also depends on lane admission, artifact pins, sandbox network, budget, package status and the sticky pre-check gate. The sheet has no override field. Section 11 then says a non-separate checker "just has that candidate refused at claim time" and section 8 holds the run if none pass. That drops the same-provider override version zero claims to keep. The basis calls the pickers "pure orders plus the override rule", which is the case its own invalidation trigger describes. Fix: make version zero a golden over the real claim inputs, including `fake` and a recorded override, or drop the "exactly" claim and name the override as a separate signed act outside the sheet.

6. **Major.** Spec sections 5 and 9. Quote: "Two roles with the same duty share a trial set" and "Each set is rotated when a new candidate is added." Author, test author and doc writer share Originate, scored by "Hidden tests pass on first attempt" on "merged work in this repository". Those tests measure the implementer. They do not measure "tests written without the implementation" or doc writing. Every Check role, including drawing checker and PDF markup reviewer, shares software canaries. A cast for CAD vision can be earned on code defects. Rotation when a candidate is added, with no full rescore on one digest, lets the set change after the candidate is known and then be compared with old scores. "Hidden" tests drawn from this repo, run in the author sandbox, are visible to the agent unless withheld. That withholding is not specified. "Criteria met", "every number in the deliverable traces to a tool output", and Summarize's "checked against a fact list" are not scriptable by equality against an owner key. Paraphrase and prose numbers need a judge, which is the basis invalidation ("A duty whose score needs a model judge"). "Tokens or subscription time as reported" copies a vendor number into the score. Trials "run through the daemon exactly as production runs are", and today's author claim moves package status. Nothing stops a trial from counting as a check. Fix: one private, owner-keyed set per role, withheld from the workspace, every candidate rescored on the same digest, blinded reports, and a job kind that cannot claim, accept or satisfy quorum. Drop measures a script cannot decide. Keep canaries behind M9, which the spec itself quotes as the plan's deferral. C4 currently depends only on "C3, review panel R3".

7. **Major.** Spec sections 6 and 10, and C-4 versus C6. Quote: "Requirements and criteria only, not the implementation", and the flow "technical preparer, then author, then test author and pre-check in parallel". Section 4's sandbox profiles are only author, checker and reviewer. The test author is Originate, so it gets the author profile, after the implementation exists. C6 adds vendor separation only. C-4 then says that split is "recommended, not enforced, for General service", while C6 and section 11 state the rule with no grade exception. Fix: give the test author a workspace that contains requirements and criteria only, and have the kernel enforce a different vendor and family for Material and Safety before the role can run. Make the General-service choice one rule in both places.

8. **Major.** Spec section 7 and section 13, and `.nuclear/changes/role-casting/plan.md` C8. Quote: "Vision: reading drawings, title blocks, dimensions against the source; never inventing a measurement." Reading a dimension is the model producing an engineering number. DN-06, cited beside it, says coordinate values come from the viewer or tool. The design-basis extractor writes "assumption entries" and can fill gaps the duty says must quote a source. Its prerequisite is only an anchoring check, not DN-03 (source authority, revision, license). Plan.md depends C8 on "DN-01 to DN-06" as a block. Section 13 says the extractor "needs only the anchoring check", then says the CAD generator waits on DN-06, which section 7 does not require for that role. C8 depends on C5, not on C6, so these roles can ship before duty-based and flow-wide kernel separation. Fix: split C8 per role. Extractor after DN-03 and a tool-confirmed locator. Drawing and PDF checks after DN-06, with numbers only from the viewer tool. Calc roles after DN-01, DN-05 and C6. No role writes an assumption the source does not state.

9. **Major.** Spec section 8, "Within the CLI constraint", and the basis assumption on effort. Quote: "Codex models through `-m` or `-c model=`". I have not rechecked the current Codex CLI grammar, so I am not asserting that the CLI rejects `-c model=`. In this repo the qualified launch passes the Codex model only as `-m` (`CodexArgs`), and attestation reads the model only from `-m` or `--model` (`argvModel`). `-c` is the ADR 0021 permission-profile channel. A model set with `-c model=` would not be the model that code compares, so a check could run on another model and still count. The basis says "Model and effort can be passed per run through the existing adapters." `ClaudeArgs` and `CodexArgs` take a model string only. There is no effort argument. Fix: name only the flags the qualified adapters and the attestation parser already treat as the model. Add effort only after a per-CLI flag is shown to work headless without a second, unparsed config channel, and correct the basis.
