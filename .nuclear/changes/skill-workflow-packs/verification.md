## Builders and review

Built by subagents under D3: Codex wrote the generator, check, sync script and their tests and generated the packs; Claude Sonnet subagents wrote the API composer and the web controls. The controller wrote the contract, workflow maps, stage cards, ode, notices, the budget script and the real-pack tests; read every builder diff; closed two gaps in `--check` (a pinned pack with no manifest, a skill list naming a file with no digest) with tests; corrected the capture-tag rule before the API builder finished; fixed the cards after the API builder found that prepared runs receive dependency outputs only through `design_inputs`; and reran every suite above on the integrated branch. After review on the pull request, the generator reads every file from the pinned commit's Git tree (`git ls-tree`, `git cat-file`) instead of the working tree, so local edits or untracked files in a checkout cannot ship under the pin's name, and a symlink in the tree stops the run; the regression test fails on the earlier generator and passes now, and regenerating both packs this way changed no byte. A second review round then led to: two upstream skills excluded from the packs because they reproduce third-party material under other licences (Superpowers `writing-skills`, Anthropic documentation; Pocock `pr`, humanlayer/humanlayer, Apache-2.0), recorded with reasons in `pins.json` and the manifests; a repository-level `packs/workflows/lock.json` with the digest of every manifest, workflow map and stage card, which the API checks before use, so an edit to a card, a map, or a manifest (including one edited to match a tampered upstream file) stops the run; `--check` requiring a complete three-stage map for every pack; a tag line with an unknown `[workflow:...]` id read as no tag; and a "Project default" choice on the card switch that clears the card's own value. The lock and the manifests live in the repository, so their trust anchor is the reviewed commit, as for every other file; they stop accidental or on-host edits and make a deliberate change visible in review. No builder's report is evidence on its own.

## Exit criteria

A package can run under the playbook, Superpowers, Pocock or Pocock Superpowers workflow, chosen per card with a project default and in New work, separate from its context profile. The two upstream packs are generated from pinned commits with digests and a `--check`; the composer puts the right stage card in the intake, author and pre-check briefs and ships the named upstream skills as verified inputs; a run whose pack is missing or tampered never starts; a sync script reports every upstream change for a person to read. Playbook briefs are byte for byte unchanged. The owner's recorded yes for the two `spec/` fields is in the Signature table of [ship](ship.md) before merge.
