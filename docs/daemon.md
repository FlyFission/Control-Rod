# Run daemon

`controlrod daemon` runs agent work on your own machine. It claims jobs from the control plane, runs an agent runtime in a per-job workspace, streams a log and reports outputs with an execution trace. It never makes a decision: releasing and accepting work belong to people, through the control plane and its kernel.

## Run it

```sh
cd daemon && go build -o ../bin/controlrod ./cmd/controlrod
CONTROLROD_API=http://localhost:7300 ./bin/controlrod daemon --parallel 3 --timeout 45m
```

| Setting | Default | Meaning |
|---|---|---|
| `CONTROLROD_API` | `http://localhost:7300` | Control plane address |
| `CONTROLROD_DAEMON_TOKEN` | contents of `~/.controlrod/daemon.token` | Bearer token for the runner API |
| `CONTROLROD_HOME` | `~/.controlrod` | Home for the token file and workspaces |
| `CONTROLROD_ALLOW_FAKE` | unset | `1` offers the fake test runtime; never set it on a real machine |
| `--parallel` | 3 | Jobs run at once |
| `--timeout` | 45m | Longest a single run may take; the whole process group is killed after it |

SIGINT or SIGTERM stops claiming, gives running jobs 30 seconds, then kills them and reports each as failed with `daemon shutdown`. A completion that cannot be sent before the daemon exits stays in the outbox and is sent at the next start.

## Runtimes

The daemon finds runtimes on `PATH` and offers those that pass the probe below:

- `claude`: Claude Code, in headless print mode under the run's sandbox policy (see "Sandbox" below).
- `codex`: `codex exec --json --skip-git-repo-check -C <workspace> [-m <model>] <prompt>`, with the run's permission profile (see "Sandbox" below). Run workspaces are not Git repositories, so the repository check is skipped.
- `fake`: test runtime. Runs `inputs/FAKE.sh` with bash, or copies `inputs/FAKE_OUT/*` into `out/`. It runs no agent CLI and takes no sandbox.

Each runtime is a registered adapter. `daemon/internal/runner/adapter.go` holds the registry; `adapter_claude.go`, `adapter_codex.go` and `adapter_fake.go` build the launch, probe the CLI and normalize its stream. Detect, Command, LaunchFor, RuntimeFor and Probe dispatch through that registry.

`controlrod sandbox-args --runtime claude|codex --policy <file> --workspace <dir>` prints exactly the argument list and environment a run would get under a policy, and runs nothing.

### Runtime probe

Finding a binary on `PATH` is not enough. At start and every 5 minutes the daemon probes each runtime it found, without signing in and without any credential:

- `<runtime> --version` must answer with exit 0;
- for Codex, when `codex login --help` lists a `status` subcommand, `codex login status` must exit 0;
- the sandbox preflight below must pass.

A runtime that fails is not offered for work, and the daemon logs why in one plain sentence with the fix. Every claim carries the probe result for each runtime, the control plane picks only runtimes reported ready, and the office lists any runtime that is not ready with its reason. The daemon never runs `claude login`, `codex login` or any other sign-in.

### Sandbox (ADR 0021; plan tasks 6.1 to 6.3)

Every job carries the sandbox policy its run is recorded under, with its digest. Before starting an agent CLI the daemon checks the policy's canonical digest against both the job and the run's record, and refuses the run if anything is missing or differs; it never starts an agent CLI unsandboxed. Each CLI keeps the owner's ordinary login: Control Rod never reads, copies or relays a token, and never writes the owner's own CLI settings.

From the policy alone the daemon builds:

- **Claude Code**: `--tools` names only the policy's tools (Bash, Read, Edit, Write, Grep, Glob; web, task and notebook tools are not qualified and never enabled), and `--allowedTools` the role's own list from `inputs/TOOLS.txt`, less any unqualified tool. `--restricted` confines the file tools to the workspace; `--strict-mcp-config` with an empty `--mcp-config`, `--setting-sources ""`, `--disable-slash-commands` and `--no-session-persistence` keep out every MCP server, user or project setting, hook, plugin and skill the run did not declare. `--setting-sources` does not block `CLAUDE.md` or auto-memory. `--settings` turns the command sandbox on with `failIfUnavailable` and no unsandboxed retry, blocks reads outside the workspace for commands and file tools alike (`permissions.blockReadsOutsideWorkingDirectories`), names the denied paths again as rules, and allows network only to the policy's hosts.
- **Codex**: launched from its verified install tree staged, content addressed and re-hashed, into a private folder in `/tmp` (`controlrod-runtimes-<uid>`, never `TMPDIR`; one stager per digest at a time), because Codex re-runs its own executable inside its sandbox and the home folder is denied whole; `--ignore-user-config`, `--ignore-rules` and `--ephemeral`; a permission profile passed as `-c` overrides that extends `:workspace` and denies the denied paths, the home folder and the daemon's home whole (the workspace inside them stays usable; a login folder or file moved elsewhere by `CODEX_HOME`, `CLAUDE_CONFIG_DIR` or a link is denied by its real path, and a login inside the workspace refuses the run), keeps `/tmp` read only and turns network off; `approval_policy="never"`; hosted web search off (`web_search="disabled"`); no notification command (`notify=[]`, which would run outside the sandbox); only the core environment for commands; and `--disable` for every Codex feature that could act outside the command sandbox (browser and computer use, apps, plugins, hooks, memories, multi agent and the rest). `sandbox_mode` is never set, because Codex ignores a permission profile whenever it is.
- **Environment**: an agent CLI receives only `HOME`, `USER`, `LOGNAME`, `SHELL`, `PATH` (less entries on WSL's Windows drives), `LANG`, `LANGUAGE`, `LC_*`, `TZ`, `TERM`, `TMPDIR`, `CODEX_HOME`, `CLAUDE_CONFIG_DIR`, `NO_COLOR` and `COLORTERM`: no provider, cloud or proxy credentials, and no sockets.

**Network.** A role that needs network names the hosts in its tools file, `network: host, host`. The control plane allows them only for public or internal work of general-service grade; otherwise the run waits with the reason. Only Claude Code can limit an agent's network to named hosts, so such a run is never given to Codex. No shipped role names any host today; pre-check and intake runs never have network.

**Preflight.** With every probe, the daemon checks that the sandbox can hold, and says how to fix it when it cannot:

- the platform has been qualified: only WSL2 so far, so on macOS and native Linux a runtime is not offered until the qualification passes there;

- on Linux and WSL2, bubblewrap (`sudo apt install bubblewrap`), and for Claude Code socat (`sudo apt install socat`), on the agent's `PATH`;
- the CLI, found on the agent's `PATH` and run with the agent's environment, is signed in (`claude auth status`, `codex login status`); the fix is the CLI's own `claude login` or `codex login`;
- no managed Codex configuration (any TOML file in `/etc/codex`), parsed as TOML, sets a key that could loosen a run (sandbox mode, permissions, approvals, web search, notification commands, features, tools, MCP servers, the command environment, profiles), naming the key to remove; a managed file that cannot be read or parsed refuses too;
- every feature the installed Codex leaves on, with Control Rod's switches applied and no user configuration, is one Control Rod has qualified. A new Codex version that turns on anything else is refused until it is qualified.

Before each launch the host checks run again without running the CLI, so nothing executes a CLI that has not yet been checked against its pin, and the launched artifact must be the one the last probe passed: a pinned version installed after the probe waits for the next probe.

**Platforms.** On WSL2 with Claude Code 2.1.318 and Codex 0.166.0, the launch passed a qualification against a scripted provider with positive and weakened controls, and a live session with the owner's login in which each CLI was refused a decoy outside the workspace (`spikes/runtime-confinement/launch_qualification.py`, `live_login_check.py`; evidence in `.nuclear/changes/workbench-ontology/evidence/phase6/`). That is not yet the protected qualification suite of plan task 6.4. macOS and native Linux are not yet qualified; the in-run attestation of plan task 6.5 is what makes each run prove its own sandbox.

### Pre-check runtime

The control plane never hands a pre-check to the runtime that authored the work. When the daemon offers only the author's runtime, the pre-check stays queued with the reason "Waiting for an independent runtime: install Codex, or proceed with a recorded owner override." and shows in the office. The owner can proceed by writing why and signing the override with a passkey, the same way as a decision: the server derives the challenge from the digest of the package id, revision, run id, the words `override-independence` and the reason, and consumes it once. The kernel allows the override only as a signed human act with a reason. It is recorded as an event with the assertion, and the pre-check record shows a shared runtime with that override. The daemon can never make it. Runtime identity is the provider and the model (the model the runtime reported, else the one asked for), and both are recorded. The same provider counts as the same runtime whatever the models: Opus checking Sonnet's work still needs the override. The kernel refuses a pre-check on the author's provider without the override.

A run's provider picks the runtime (`anthropic` or `claude`, `openai` or `codex`, `fake`). A job for a runtime this machine lacks fails at once without creating a workspace.

## Workspace

Each job gets `~/.controlrod/work/<package>/r<revision>/<role>-<round>-<run>/` with `inputs/` written from the job and `out/` for deliverables. Input names that would land outside `inputs/` refuse the whole job before anything is written. The only prompt an author or intake agent receives is: "Read inputs/BRIEF.md and do exactly what it says. Write every deliverable into out/."

A pre-check on Claude Code or Codex uses a different directory. If the walk from the usual work directory up to `/` contains an instruction name, the working directory is placed under `/var/tmp/controlrod-checker-<uid>` instead, so that walk does not pass a repository or a home-directory instruction file. The match is case-insensitive on each path segment and includes `CLAUDE.md`, `CLAUDE.local.md`, `AGENTS.md`, `AGENTS.override.md`, `GEMINI.md`, `.claude`, `.codex`, `.agents`, `.grok`, `.opencode`, `.mcp.json`, and `hooks`. A deliverable path with one of those segments is not mounted. The brief lists the withheld names in a JSON code block, and a name with a control character or a newline is rejected before it is written. The files that remain are a real directory at `inputs/deliverables/`, not a symlink, and that directory is read-only. Each deliverable artifact digest is the SHA-256 of the raw bytes, the same digest an author output of those bytes would have. The length-prefixed encoding is only the tree digest.

On Linux and WSL2 the mount is bubblewrap: `--die-with-parent`, `--unshare-pid`, `--unshare-ipc`, `--ro-bind / /`, `--proc /proc`, and `--dev /dev`. The pid namespace and the fresh procfs mean `/proc/<host-pid>/root` and `/proc/<host-pid>/fd` are not a path back to a writable host mount. `--unshare-ipc` isolates System V IPC. The boundary that covers every Unix socket, including an abstract-namespace socket that has no filesystem path, is a seccomp filter passed with `--seccomp`: `socket(AF_UNIX, ...)` returns EPERM. A syscall number at or above `0x40000000` (the x32 bit, which shares `AUDIT_ARCH_X86_64`) returns EPERM before any other check, so an x32 `socket` cannot fall through to allow; that is also how an i386 `socketcall` number is rejected when it is presented in that form. `io_uring_setup`, `io_uring_enter` and `io_uring_register` return EPERM (425, 426 and 427 on both x86_64 and aarch64), because `IORING_OP_SOCKET` creates an `AF_UNIX` socket without the `socket` syscall. `socketpair(AF_UNIX)` is allowed only for `SOCK_STREAM` and `SOCK_SEQPACKET`, ignoring `SOCK_NONBLOCK` and `SOCK_CLOEXEC`. Those types are already connected: `connect` on a `SOCK_SEQPACKET` pair returns `EISCONN` (errno 106 here), so the end cannot be pointed at a host listener. `SOCK_DGRAM` can `connect` or `sendto` again, so it returns EPERM. A `socketpair` in any other domain stays allowed. Node and libuv use an `AF_UNIX` `SOCK_STREAM` pair for stdio. `AF_INET` and `AF_INET6` stay allowed so the CLIs can open HTTPS. `accept` is not denied: the checker inherits only standard input, output and error, plus the verified executable and this filter file, and none of those is a listening socket. Go marks every other file descriptor close-on-exec. The filter file is closed after bubblewrap reads it. `pidfd_getfd` cannot see a host process because the checker is in a new pid namespace. An unknown CPU architecture, or a bubblewrap without `--seccomp`, refuses the check. The path masks stay as well: a tmpfs on `/run/user/<uid>` when that directory exists, on `XDG_RUNTIME_DIR` when that is a different real directory, and on `/run/dbus` when that directory exists, and `/dev/null` over the docker socket, the system bus socket, `SSH_AUTH_SOCK`, and the `S.gpg-agent` sockets. A symlink is masked at its target too, so `/var/run` pointing at `/run` does not make bubblewrap try to create a file through the symlink. The checker's environment drops `DBUS_SESSION_BUS_ADDRESS`, `DBUS_SYSTEM_BUS_ADDRESS`, `SSH_AUTH_SOCK`, `DOCKER_HOST`, `GNUPGHOME`, and the related agent variables. Nothing in this tree was found that needs an `AF_UNIX` connect. Writable exceptions are only: `scratch/`; a tmpfs on `/tmp`, with the child's `TMPDIR` set to that tmpfs; the active CLI's credential file when it is a regular file owned by this user and contained in the login directory; and empty per-run directories mounted over the real session directories. Claude's credential file is `.credentials.json`. Its session directories `projects`, `debug`, and `todos` (`CLAUDE_CONFIG_DIR` or `~/.claude`) are not writable views of the real directories: each real directory that already exists is covered by a new per-run directory (`login-overlay-<random>`, not a shared `login-overlay`) that the daemon removes after the run. A leftover directory from an earlier run is not reused. Codex's credential file is `auth.json`, and `sessions` and `log` (`CODEX_HOME` or `~/.codex`) are covered the same way. A session path that is missing is not created on the host. A session path that is a symlink is not mounted, so it cannot grant writes to the symlink's target. The other vendor's directory is not mounted writable. After the tmpfs, the login directory is mounted read-only again before those exceptions, including when it lives under `/tmp`. `settings.json`, `CLAUDE.md`, `CLAUDE.local.md`, `AGENTS.md`, `AGENTS.override.md`, `config.toml`, `hooks`, `skills`, `agents`, `commands`, `plugins`, and `rules` stay on that read-only directory. The hash covers the directory itself, so a directory that appears during the check voids it, and each of those names, including when the name is absent. A file records its kind, mode, and raw bytes, and a file over the 20 MB cap fails the hash. After the tmpfs, `StageRoot` (`/tmp/controlrod-runtimes-<uid>`) is mounted read-only again when that directory exists, and so is any workspace that lived under `/tmp`. The verified executable's descriptor is mounted onto `VerifiedPath` when the command is `/proc/self/fd/N`. An empty `VerifiedPath` does not bind a descriptor; a descriptor command without that path fails closed. The daemon accepts the launch only when the sandboxed child is that file. On macOS there is no bind mount. Deliverables are the real directory inside the working directory, so the CLI can read them with working-directory reads. Seatbelt cannot mount one directory over another, so the Linux overlays are not applied on macOS and the CLI still sees the real `projects`, `debug`, `todos`, `sessions`, and `log` paths. There is no documented variable that moves only those directories and leaves the credential file in the real login directory: `CLAUDE_CONFIG_DIR` and `CODEX_HOME` move the credential file as well, so a checker does not point them at a disposable directory. Claude is already started with `--no-session-persistence`, and Codex with `--ephemeral`. The Seatbelt profile therefore denies reads of those real session directories, using the path the process would open and not a symlink target. It allows reads and execution, denies every `file-write*`, denies outbound Unix sockets (`network-outbound` to `unix-socket`), and allows writes only on the canonical scratch path, one directory for this run under the canonical temporary directory (not all of `/tmp`), and the credential file under the same checks. A blanket `mach-lookup` deny is not applied: the process needs the bootstrap server, and no narrower set was shown to be safe. The per-run temporary directory is removed after the run. Every allowed write path is passed through `filepath.EvalSymlinks` first. The profile was not executed on a Mac, so a sandboxed checker on macOS is refused until `CONTROLROD_SEATBELT_QUALIFIED=1`. Any other value stays refused. The refusal says `macOS checker sandbox not yet qualified`. The fake runtime does not use this mount. A checker does not install the permission hook: that hook writes outside scratch.

The checker may write `scratch/verification.json`, when the brief asks `scratch/criterion-results.json`, and evidence files under `scratch/evidence/`. The daemon checks the first against the checker schema (or a full `VerificationRecord`) and the second against `CriterionResultSubmission`, and moves them onto the completion under those names. Evidence files are capped at the same 20 MB per file and 100 MB total and are uploaded as `evidence/<relative name>`. Duplicate JSON keys and null arrays are refused. Any other write, or any change to the deliverable tree or to a protected login path, voids the check. The tree hash length-prefixes path, kind, mode, and payload, streams file bytes, and fails closed above the existing 20 MB file cap, the 100 MB total, or `MaxOutputTotal/4096` entries. Symlink targets are not read. A void sets the completion failed, records a policy notice, and does not attach a passing verification. The outcome text for a write is `wrote_files`. A missing mount, a hash that cannot be computed, or a file that fails the schema fails the same way. The fake runtime still writes `out/`, including separate evidence files referenced as `checker:<relative file name>`.

Claude checkers also pass `--disallowedTools mcp__*,Agent` and `--max-turns 8`, and set `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` and `autoMemoryEnabled: false` on the `--settings` argument. Those are the controls Claude Code documents for turning auto memory off for one process. They were not remeasured against a Claude Code binary here. The turn bound is the one `spikes/runtime-confinement/launch_qualification.py` already passes to a headless Claude print session, not a new measurement. `--fallback-model` is not passed. `--safe-mode` is not passed: Claude Code was not available here, so it was not shown to keep an OAuth or keychain login in a headless `-p` session. No flag in this tree was shown to suppress user-level `~/.claude/CLAUDE.md` or `~/.codex` `AGENTS.md` while keeping that login; `--setting-sources` does not. Those files stay read-only, and a change voids the check. Codex checkers use the `--ignore-user-config`, `--ephemeral` and `--disable multi_agent` flags already on every Codex launch. `HOME` stays the owner's home. The daemon does not create a private home and does not read or copy login tokens.

The agent's environment has every `CONTROLROD_` variable removed, so it never sees the token or the API address. What a package manager set for the script that started the daemon is removed too: under `pnpm cr` that is every `npm_*` and `pnpm_*` variable, `INIT_CWD`, `PNPM_SCRIPT_SRC_DIR`, and the `node_modules/.bin` and `node-gyp-bin` entries put in front of `PATH`. They describe Control Rod's launcher, and some break tools in the agent's own shells (nvm refuses to load while `npm_config_prefix` is set). A user's own `NPM_CONFIG_*` or `PNPM_HOME` stays. For the fake test runtime that is the whole rule. An agent CLI (Claude Code, Codex) instead receives only the allowlisted environment described under Sandbox above, so none of this reaches it either. Claude Code runs also get `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`, so the agent cannot start a background shell or background agent that outlives its turn.

## Run attestation

A sandboxed pre-check is a counted check. Before the process starts, the daemon refuses it when the generated config or the command environment names a custom base URL (`base_url`, `model_provider`, `*_BASE_URL`, `OLLAMA_HOST`), when Claude is passed `--fallback-model`, or when Codex is missing `--ignore-user-config` or `--disable multi_agent`. The model must be an entry in `daemon/internal/runner/models.json`. The executable's SHA-256 must be the pin the server sent, or a digest registered for that harness. The file name is not used. Author and intake launches do not go through this gate, and the fake runtime is not a counted check.

When the check is otherwise allowed to count, the daemon signs an Ed25519 attestation over the statement in [ADR 0022](adr/0022-run-attestation.md). That statement includes the executable digest, the sandbox policy digest, a digest of the generated config arguments (including `--model` / `-m`), the registry host as the effective endpoint, every model name in the stream, the platform, the probe result, the workspace hashes, the requested model, the checker attempt id, the deliverable content digest, and a digest of the verification submission. The probe result is `not-run` until an in-run probe is qualified. The endpoint label is `endpoint not enforced` because there is no egress proxy. A stream name outside the pinned entry, including an alias or a second model, voids the check. Counted checks also refuse `--flag=value` and attached short options (`-cX`, `-c=X`, `-pX`, `-p=X`, `-mX`) that name a custom base URL or a Codex profile. A settings file path is refused, and so is settings JSON that names a base URL, `apiKeyHelper`, or a provider route. `ANTHROPIC_BEDROCK_BASE_URL`, `ANTHROPIC_VERTEX_BASE_URL`, `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`, `OPENAI_API_BASE`, and the proxy variables are refused when they are on the command environment. Claude's `-p` is the print prompt and is not a profile. Deliverable and evidence names are ordered by UTF-16 code units, the same order the server uses.

The private key is stored in the OS keychain. macOS uses Security.framework, so the secret is not a process argument. Linux `secret-tool store` reads the secret on stdin. A lookup that fails for any reason other than a missing item does not create a replacement key. `controlrod attestation-public` creates a key only when none is stored, and prints the key id and the public key. An administrator enrolls that public key with a passkey (`daemon.enroll-key`) and retires it with `daemon.retire-key`. A retired key stops counting at once. Tests may point `CONTROLROD_TEST_ATTESTATION_KEY` at a mode `0600` file only when `CONTROLROD_ALLOW_FAKE=1`. The macOS Keychain was not executed in this change, and no real Claude Code or Codex binary was launched.

The server checks the signature, then the run id, the attempt id, the requested model, the deliverable digest, and the verification digest, and only then stores the nonce. It records `attestation_verified` on the run and, when the check counts, on the verification. The kernel does not read that field. A missing or failed attestation does not count, does not leave a verification, and is recorded as an inconclusive checker attempt. There is no switch that lets production count an unattested check.

## What it reports

- **Log:** raw stdout and stderr lines (stderr prefixed `[stderr] `) about once a second, with a label the daemon derives from event types only, such as `Edit: report.md`, `Run: python3`, `Fetch: standards.example.org`, `Search` or `Finishing`. Labels are built from tool names and short plain tokens (a file basename, a host, a command's first word, at most 120 characters), never from model prose.
- **Completion:** every regular file under `out/` (20 MB per file, 100 MB in total; symlinks fail the run), an `ExecutionTrace` with SHA-256 digests of every input and output, the runtime name and its `--version`, start and finish times, and what ran: `runtime_mode` (`print` for every real run today, see ADR 0020), the requested model (`default` when the run names none), the model the runtime reported in its own stream, the permission mode, the tool allowlist and the sandbox. When a run names a model the daemon passes it (`--model` for Claude Code, `-m` for Codex). The control plane names `default` today, so the runtime's own default is used and the reported model is the record of what ran. An intake run attaches `out/package.json`. A fake pre-check attaches `out/verification.json` and any other files it wrote under `out/`. A Claude or Codex pre-check attaches `scratch/verification.json` after the schema check, `scratch/criterion-results.json` when that file is present and valid, and regular files under `scratch/evidence/` as `evidence/<relative name>`, and only when the deliverable tree, the protected login paths, and the rest of the workspace still match the hashes taken before the process started.

## Run custody

- **Claim:** each claimed run comes with a claim token and a lease (90 seconds by default). The daemon presents the token on every log post and on the completion; a post with another token is refused.
- **Heartbeat:** every log post renews the lease. When the agent is quiet the daemon still posts an empty batch at the heartbeat interval the control plane gives it (a third of the lease).
- **End of turn:** a print-mode run is over when the runtime reports the end of its one turn (Claude Code's final `result` event, Codex's `turn.completed` or `turn.failed`), not only when its process exits. If the process is still there 30 seconds after that report (background work, a hung hook or child), the daemon ends every process of the run, snapshotting `out/` while they are frozen, and completes the run on what the runtime reported: succeeded for a successful report, failed for a failed one. A notice in the run's events says so. A run whose process exits on its own is unaffected, and its exit status still decides. Without this, a finished run showed as running until the 45-minute timeout and was then recorded as failed with `timeout`.
- **Lost:** if the lease lapses (the daemon died, slept or lost its network), the control plane marks the run `lost` with the reason, shows it in the office, and requeues nothing on its own. Only the owner can requeue it, from the package view. A log post for a run that is no longer running gets a refusal, and the daemon then ends the agent process.
- **Completion and outbox:** the daemon writes each completion to `~/.controlrod/outbox/<run>.json` (owner read-only) with a key chosen once, then posts it. A network error, 408, 429 or a server error is retried with the same key, waiting 1 second and doubling up to 30 seconds; after six tries it waits in the outbox. The daemon tries it again at start, then 30 seconds later, and waits twice as long after each further failure, up to 15 minutes, with one log line per try that gives the count and the next wait. It is never dropped for failing: only a recorded completion or a final refusal takes it out of the outbox. A restarted daemon tries every waiting completion at once. Reports that an earlier daemon's run process is gone back off the same way. A repeat with the same key gets the stored receipt back. Any other refusal is final: the file moves to `outbox/refused/` as evidence and is not sent again.
- **Stop:** the owner can stop a run from the package view. A queued run stops at once. For a running run the request is recorded first (`run.stop-requested`); the daemon learns it from the reply to its next log post or heartbeat, kills the process group, and completes the run as `stopped`. The run shows as stopping until then, which can take up to one heartbeat interval. Asking again changes nothing. A stopped run never moves its package; the owner can requeue it, or return or reject the package.
- **Refusals while applying a completion** (an unsafe output name, an invalid trace, a pre-check with no outcome, intake with nothing to show, a kernel refusal) leave the run `failed` with the reason on the record, and the receipt says so. An invalid trace is never dropped silently.

## Tests

`go test ./...` runs a fake control plane and the fake runtime: workspace layout, path-escape refusal, label derivation from a recorded stream, output and trace digests, schema validation of the trace and verification record against `spec/generated/json-schema`, timeout and process-group kill, graceful shutdown, and checks that the token never reaches the agent, the logs or a request body.
