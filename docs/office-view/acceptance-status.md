# Office view acceptance status (plan task 4.7)

Each approved case in [acceptance.md](acceptance.md) maps to the tests that hold it, or to a recorded deferral with its reason. "Met" means every Then and Never clause is held by a test assertion, not by a reading of the code; "partly met" names what is held and what is deferred. Phase 4 closes with every case here; the deferred parts are owned by the plan tasks or owner decisions named.

Plan task 4.7 asks for the cases on both themes. The workflows below are asserted in component and API tests, which do not depend on a theme. What a theme can change is held separately: a theme supplies only scene art beneath the app-owned semantic layer (contract 4.2, `contract.test.ts`), and the rendering harness (`e2e/office-harness.spec.ts`) measures every state shape, mark, lens and the Safety ring on both themes. No workflow is run once per theme.

Where a client test is cited, its server responses are mocked; the matching server behaviour is cited from the API tests on the same row.
