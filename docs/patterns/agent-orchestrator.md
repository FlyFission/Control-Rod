## Verdict

Control Rod already leads `agent-orchestrator` on its core trust boundary: process containment (`SpawnReceipt` with `BootID`, `ProcessStart`, and `Generation`; systemd cgroup v2 freeze and kill; pidfd signaling; seccomp `AF_UNIX`/`io_uring` deny; `HostGitArgs`/`HostGitEnv`; the `AwaitingConfinement` fail-closed gate; and fail-closed `leaseClock`), Rust kernel state transitions, human passkey sign-off, independent checkers without author transcripts, zero telemetry, WCAG 2.2 AA contrast across Looks A/B/C, and support for non-code engineering deliverables.

Where `agent-orchestrator` provides battle-tested design input is in operational hardening for Control Rod issues `#118`–`#133` and board slices `M5`–`M8`. In its issues and PRs ([`#7402`](https://github.com/OrchestratorInc/agent-orchestrator/issues/7402)–[`#8887`](https://github.com/OrchestratorInc/agent-orchestrator/issues/8887)), daemon, worktree and state-machine defects recur more than UI defects do. That is a reading of the issue list, not a measured rate: no script or count is recorded for it. It is the reason this note puts daemon and worktree hardening (`#118`–`#120`) ahead of widening CLI adapters (`#125`).

## Not borrowed

- **Auto-injecting CI failures, PR comments, or merge conflicts into worker sessions** (`lifecycle/reactions.go:170-303`): driving code mutations directly from untrusted external text violates Control Rod's human-gate custody model.
- **Reusing live reviewer sessions across commits or idle-timer autonomous review loops** (`autoreview/coordinator.go:86-161`): Control Rod pre-checks must start fresh per pinned revision with zero author transcript.
- **Reviewers invoking `gh api` directly or host-trusted unsandboxed mode** (`review/prompt.go:33-89`, `reviewgateway/gateway.go:73-97`): only the controller may publish GitHub check status, and execution stays fail-closed confined.
- **Interactive TUI / PTY / ConPTY / tmux scraping and detached persistent chat hosts** (`sessionguard/`, `persistenthost/`): a high-defect surface in AO's issue corpus ([`#7523`](https://github.com/OrchestratorInc/agent-orchestrator/issues/7523), [`#7606`](https://github.com/OrchestratorInc/agent-orchestrator/issues/7606), [`#7434`](https://github.com/OrchestratorInc/agent-orchestrator/issues/7434), [`#8105`](https://github.com/OrchestratorInc/agent-orchestrator/issues/8105), [`#8856`](https://github.com/OrchestratorInc/agent-orchestrator/issues/8856)); Control Rod's headless lease-bound cgroup model is cleaner and safer.
- **Full login-shell environment forwarding** (`docs/daemon-environment.md:122-169`): risks leaking host API keys into confined agents.
- **AO's SQLite+CDC daemon store and `workspacewatch`**: Control Rod's control plane, durable receipts/outbox, and post-freeze capture are simpler and authoritative.
- **AO's relaxed button contrast, sub-11px fonts, icon-only status glyphs, and 4-lane PR-only board**: preserve Control Rod's WCAG 2.2 AA contrast floor, `11px` `--fs-chip` floor, symbol+word tokens, and 6-column custody pipeline.

## Battle-scar hardening tests

Drawn from `agent-orchestrator` issues and PRs ([`#7402`](https://github.com/OrchestratorInc/agent-orchestrator/issues/7402)–[`#8887`](https://github.com/OrchestratorInc/agent-orchestrator/issues/8887)) to test Control Rod slices before scaling adapters or UI features:

- **Crash and concurrency (`#119`, `#120`):** Kill and restart the Go daemon mid-run and mid-approval; delete a child repo then terminate or archive its session (AO [`#8691`](https://github.com/OrchestratorInc/agent-orchestrator/issues/8691), [`#8676`](https://github.com/OrchestratorInc/agent-orchestrator/issues/8676)); create worktrees containing symlinks plus `node_modules`/`.venv` (AO [`#8699`](https://github.com/OrchestratorInc/agent-orchestrator/issues/8699)); verify idempotent turn-scoped stop (AO [`#8820`](https://github.com/OrchestratorInc/agent-orchestrator/issues/8820)), bounded retry budget with dead-letter state (AO [`#8397`](https://github.com/OrchestratorInc/agent-orchestrator/issues/8397)), and UTC-only timestamp enforcement (AO [`#8835`](https://github.com/OrchestratorInc/agent-orchestrator/issues/8835)).
- **GitHub PR check and SCM (`#131`, `#132`):** Evict terminal PRs (`merged`/`closed`) from the poll loop (AO [`#8883`](https://github.com/OrchestratorInc/agent-orchestrator/issues/8883)); reduce checks to latest-per-check-name on the current `head_sha` (AO [`#7780`](https://github.com/OrchestratorInc/agent-orchestrator/issues/7780), [`#8879`](https://github.com/OrchestratorInc/agent-orchestrator/issues/8879)); exclude draft PRs (AO [`#8479`](https://github.com/OrchestratorInc/agent-orchestrator/issues/8479)); verify sanitization prevents internal instruction wrappers from leaking into notifications, receipts, or PR checks (AO [`#8762`](https://github.com/OrchestratorInc/agent-orchestrator/issues/8762), [`#8763`](https://github.com/OrchestratorInc/agent-orchestrator/issues/8763)).
- **Adapters and auth (`#125`, `#127`):** Run an isolated-`HOME` non-interactive boot test per CLI to catch first-run wizards (AO [`#8862`](https://github.com/OrchestratorInc/agent-orchestrator/issues/8862)); never wipe saved auth on transient keychain or file read errors (AO [`#8728`](https://github.com/OrchestratorInc/agent-orchestrator/issues/8728), [`#8727`](https://github.com/OrchestratorInc/agent-orchestrator/issues/8727)); ensure a single-check failure does not hide healthy CLIs (AO [`#8850`](https://github.com/OrchestratorInc/agent-orchestrator/issues/8850)).
- **Dashboard (`#124`, `#133`):** Enforce a single-observer store with no per-row pollers (AO [`#8620`](https://github.com/OrchestratorInc/agent-orchestrator/issues/8620)); preserve selection across diff updates (AO [`#7510`](https://github.com/OrchestratorInc/agent-orchestrator/issues/7510)); keep forms dirty on refused save (AO [`#8861`](https://github.com/OrchestratorInc/agent-orchestrator/issues/8861)); run a Playwright offline and no-third-party-request check (`#133`).
