# Pattern note: Headroom

- **Source:** Headroom, a local layer that shrinks tool output, logs and history before a coding agent sends them to a model, https://github.com/headroomlabs-ai/headroom
- **License:** Apache-2.0 (permissive, so rule 4 does not bar reading its code; this note still carries ideas only)
- **Read:** 2026-11-18, shallow clone at commit `53a2521`. Read in full: `AGENTS.md`, `.github/PULL_REQUEST_TEMPLATE.md`, `docs/adr/0003-a1-b-release-benchmark.md`, `docs/adr/0004-black-box-release-benchmarks.md`, `docs/adr/0005-release-overrides-and-fail-closed-policy.md`, `headroom/managed_block.py`. Read in part: `README.md` (first 200 lines and the "When to use", "What's inside", "Pipeline internals", "headroom learn" and "Telemetry" sections), `REALIGNMENT/00-overview.md` and `REALIGNMENT/12-decisions-needed.md` (first 40 lines each), `headroom/learn/writer.py` (first 60 lines, including `_find_managed_block`), the module headers of `headroom/learn/analyzer.py`, `loops.py` and `verbosity.py`, `headroom/log_safety.py`, `headroom/savings_ledger.py` and `headroom/rollout.py`, and the field lists and `main` of `scripts/pr-governance.py`. Not read: `REALIGNMENT/01-bug-list.md` and the later phase files, the Rust core, the compressors, the CCR store or the tests. Nothing here was run.
- **This note carries ideas only.** No code or configuration is copied and the prose is reworded. Names of files, flags and fields are kept where the idea cannot be stated without them. A comparison of lower-cased six-word runs against the files above found none shared except the source URL and an ADR file name; an independent read-only review checked each row against its sources (change record `headroom-patterns`).

Headroom is a token-saving product, not a governance system, and Control Rod has no use for its compressors. What carries over is how it treats text written into instruction files, how its release evidence fails closed, and what its own post-mortem (`REALIGNMENT/`) says about a gateway that edits requests on their way to a provider. Its published savings figures were not reproduced and nothing here relies on them.

## Ideas

| # | What Headroom does | Fit in Control Rod | Decision |
| --- | --- | --- | --- |
| 1 | Its `learn` command writes lessons drawn from session transcripts into a marked section of `CLAUDE.md`, `AGENTS.md` and similar files; the default target is a gitignored `CLAUDE.local.md`. Transcript text could contain the section's closing marker, so the rest of the lesson landed outside the section, survived later rewrites, and could sit in a committed, shared instruction file. The fix escapes HTML comment openers and closers before writing, ends the section at the first closing marker, and ignores markers inside code fences. | Control Rod writes nothing into the owner's own CLI settings or instruction files (`docs/daemon.md`; ADR 0021, still Proposed). In author runs, agent commands and file tools are denied the login folders (`ClaudeSettings` in `daemon/internal/runner/sandbox.go`, and the Codex profile). In pre-checks, the instruction, hook, skill and settings names in the login folder are mounted read-only (`protectedLoginNames` in `checker.go`) and the checker starts in a clean directory. Not covered: instruction files an author run writes into its own workspace. Those are deliverable content; later author runs in the same workspace load them (`runtime.go` notes that `--setting-sources` does not block `CLAUDE.md`), and nothing stops them reaching a merge. | **Already have** for the login folders. **Adopt** a threat-model row that names the workspace gap as open (added in this change). Any future Control Rod feature that writes derived text into a Markdown file an agent loads must escape comment delimiters, keep to one marked section, and show the diff to a person first; derived text never goes into hooks, settings or executable files. |
| 2 | Release evidence has exactly four outcomes: pass, fail, inconclusive, and skipped because the policy version does not require it. Evidence that is missing, stale, mismatched, revoked or of the wrong schema can never yield a pass. An override names its scope, reason, human approver and expiry, never holds a credential, and appears in the gate result. A revoked qualification is new, linked evidence, not an edit. | The qualification suite in `docs/plan/multi-provider-design-plan.md` already says a dropped quorum seat is inconclusive, never a pass. Whether verification checks have a first-class "cannot determine" outcome is xerj.md row 6, still open. Kernel decision functions are a trust surface. | **Open question for the owner.** This is a worked answer to xerj.md row 6, including how an override expires. No kernel change proposed. |
| 3 | The headline release benchmark compares the same build with optimization off against the same build with it on. The two arms must agree on source commit, artifact digest, rollout snapshot, model, agent, task set, environment image and resource limits; each task runs in both arms, in random order. The producer states whether identities matched, and any mismatch makes the result inconclusive. | ADR 0021 qualifies each new CLI version with paired arms: the same probe run unsandboxed as a positive control, and a deliberately weakened policy that must fail. Nothing yet says those arms must share every identity except the one under test. How qualification is judged decides which CLIs may run, so changing it is the owner's call. | **Adapt, later, owner's call.** When qualification is built, each paired comparison records both arms' identities and reports a match verdict; a mismatch is inconclusive. |
| 4 | Benchmark infrastructure exercises only the public interface of the immutable candidate, verifies the artifact digest before installing it, and gets no publish credentials and no provider secrets through the release evidence. When a provider or the runner breaks, the result is inconclusive, and it does not count as the candidate's failure by default. | Same qualification work. Run attestation signs what the daemon observed (`daemon/internal/runner/attest.go`; ADR 0022 is Proposed and not yet qualified on real CLIs). | **Adapt, later**, together with row 3. |
| 5 | Its savings ledger first stored one list-priced dollar figure per event, with no record of the cache read and write mix. When that pricing basis proved wrong, history could not be corrected, since the stored figure kept no trace of its parts. Version 2 stores the shape of each event beside the dollar figure, so totals can be derived again. | `daemon/internal/runner/events.go` stores input, output and cached token counts exactly as the CLI reported them, and a field the CLI did not send stays empty rather than zero. | **Already have** for token counts. Keep the rule for budgets and any cost view: store the readings beside any derived figure. |
| 6 | The post-mortem found that an aggregate statistics component changed a compression decision during the very request it was observing. The planned fix makes it observe only, with any recommendation applied between releases. | The kernel is deterministic (ADR 0012), so its decisions should depend only on the inputs recorded for that decision. | **Adapt as a review question** whenever run telemetry starts to feed a decision path. No change proposed. |
| 7 | The realignment plan's first rule for the proxy is that untouched content passes through byte for byte. It requires forwarding raw request bytes instead of re-encoding JSON (the post-mortem found re-encoding broke provider prompt caches), a SHA-256 round-trip test, removing its own `X-Headroom-*` headers before the upstream call, pinning the order of provider beta headers for a session, and sorting tool lists deterministically. It names header changes as a fingerprinting risk for subscription logins. | ADR 0014 makes stripping Control Rod headers a condition for agentgateway, which is not built; only the spike exists. Subscription CLIs keep their own login and do not route through it (ADR 0014, ADR 0021). Control Rod would qualify agentgateway rather than write the proxy. | **Required, not built** (ADR 0014 condition). **Adopt when agentgateway is qualified:** show that it forwards bytes Control Rod does not mean to change unchanged, with a round-trip digest test. |
| 8 | A cache aligner warns about volatile text that would invalidate a cached prompt prefix and never rewrites the prompt itself. | `events.go` captures cached tokens, the case story shows them per usage event (`apps/web/src/features/case/story.ts`), and budgets sum them per run (`services/api/src/budgets.ts`). No view shows the share of a run's input served from cache. | **Open.** A cache-read share per run is cheap. Not proposed now. |
| 9 | Log lines describe a failure by exception type, code location, error number and IDs, never by the exception message, because those messages often repeat request content or a database address. Payload content is logged only after an explicit operator opt-in. | `docs/daemon.md` says tests check that the daemon token never reaches the agent, the logs or a request body, and that the daemon streams the agent's own output lines as the run log. There is no general rule for exception messages in logs. xerj.md row 4 left a related check open. | **Open check for the owner**, alongside xerj.md row 4. |
| 10 | Its pull request template asks for the environment, exact steps, observed result and what was not tested. A script reads the PR body, comments, and labels the PR as needing author action when any of those is blank. | Control Rod's template asks for evidence but not for what was left untested; change records carry gaps, but a PR without a record has nowhere to say so. | **Adopt** a "Not tested" line in the template (added in this change). **Skip** the automated check for now: wiring it touches `.github/workflows/`, a trust surface. |
| 11 | A `learn` command mines failed sessions for repeated failing calls and for re-runs of a truncated command, and ranks lessons by how much repetition wasted. | Lessons from operation are nuclear-grade's job (its OPEX skill), not Control Rod's. | **Skip here.** Raised with nuclear-grade instead. |
| 12 | Versions across manifests are kept in step by a script, a CI guard stops hand edits to the changelog, and the changelog is generated from commit titles. | Every version is `0.0.0` and there is no release job. | **Skip now.** Revisit with the first release. |

## Not borrowed

- **Telemetry on by default.** Headroom sends an anonymous usage beacon unless the user turns it off. That cuts against an owner-local workspace; do not adopt it.
- **One model call in place of regex analysis.** Its failure analysis replaced pattern matching with a single model call over the session (loop detection stays mechanical). In Control Rod the kernel decides every state change (README), and a model checker's verdict is an input it weighs by rule (ADR 0022), not a replacement for the rules.
- **Compression of evidence.** Any lossy transform of what a checker reads or what a record holds would break custody. If context shrinking is ever added, it stays outside the evidence path, and the original's digest is recorded next to anything shortened.
- **Its savings figures.** Not reproduced; not quoted here.
