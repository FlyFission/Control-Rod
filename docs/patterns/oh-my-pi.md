# Pattern note: Oh My Pi (`omp`)

- **Source:** Oh My Pi (`omp`), a terminal coding-agent harness with multi-provider routing, model catalogs, presets, and an agent hub, https://github.com/can1357/oh-my-pi
- **License:** MIT (permissive, compatible with Apache-2.0 under `AGENTS.md` rule 4; this note still carries ideas only)
- **Read:** 2026-11-24, public repository documentation and due-diligence review recorded for branch `feat/omp-patterns-adapter-casting-desk`. Nothing here copies upstream source code, configuration files, schemas, or prose.
- **This note carries ideas only.** No code or configuration is copied and all descriptions are written in Control Rod's own words. Flag names, subcommands, and concept labels are kept only where the idea cannot be stated without them.

Oh My Pi is a terminal-first coding harness built around breadth of providers, role-based model routing, and rich local developer tooling. Control Rod is a browser-first governance control plane built around blind cross-vendor checking, OS-level confinement, and passkey-signed records. The two complement each other: Control Rod can seat `omp` as a multi-provider runtime adapter under its own OS sandbox and bring `omp`'s role, effort, preset, and failover ergonomics into the web app without sacrificing Control Rod's trust boundaries.

## Deep extraction: secondary high-value mechanisms

Beyond the primary adapter, catalog, and Casting Desk ergonomics above, six secondary mechanisms in `oh-my-pi` solve hard runtime problems cleanly and map onto Control Rod's daemon and control-plane roadmap when bounded by Control Rod's governance rules.

### 1. Zero-context-tax stream rules and unified rulebook discovery

- **Mechanism:** `oh-my-pi` normalizes rules discovered from multiple editor and harness conventions (`.omp`, `.agents`, Cursor, Windsurf, Cline, GitHub) into one canonical shape with priority-based deduplication by rule name. Rules carrying match conditions stay out of the system prompt until triggered, avoiding context tax. During streaming, a linear-time regex automaton monitors text, thinking, and tool-call deltas without catastrophic backtracking; multi-file edit payloads are projected into per-file hunks so path-scoped rules do not misfire across sibling files. Rules that do not interrupt mid-stream defer until block completion, while structural AST checks run synchronously right before tool execution.
- **Fit in Control Rod:** The daemon already streams structured events from adapters. Adopting linear-time stream scanning and per-file edit-hunk projection gives Control Rod low-overhead stream guardrails (for example, catching forbidden patterns or runaway edits early) and lets projects import existing team rule files into `packs/` or project briefs without paying a prompt-size penalty on every turn.
- **Governance boundary:** Stream rules are advisory or interrupt-level runtime guardrails, never a security or compliance boundary. They must never replace OS confinement (ADR 0021), OPA policies under `policies/`, or kernel decision functions in `kernel/`. Any rule-triggered abort must be logged as a run event rather than silently rewriting history.

### 2. Typed error classification, replay-safety veto, and failover triggers

- **Mechanism:** `oh-my-pi` routes non-compaction failures through a normalized error classifier that separates transient transport/envelope/HTTP errors, rate or usage limits, classifier refusals, account-policy denials, and hard failures. Before retrying, it enforces a replay-safety veto: once non-whitespace visible text, images, or executed tool calls have been committed, blind replay is blocked (with a narrow exception only when every emitted tool call has a proven non-executed synthetic result). Retries use capped jittered backoff, while configurable `fallbackOn` policies control whether hard errors or usage limits consult a role's fallback chain with a fresh retry budget.
- **Fit in Control Rod:** Directly informs the daemon implementation of ADR 0024 Decision 6 (author-only failover). Typed classification lets the daemon distinguish transient network blips (safe to retry on the same seat) from quota exhaustion, sign-out, or account denials (triggering logged failover to the next Author candidate on the Casting Sheet), while the replay-safety veto prevents duplicating partial workspace mutations.
- **Governance boundary:** Failover chains apply **strictly to Author seats**; every failover records origin, target, and classified reason on the run and flags the card for human review before merge (ADR 0024 Decision 6). Blind Checker and Refuter seats must hold on failure or quota exhaustion—never silently fail over or rotate models to shop for a pass (ADR 0023).

### 3. Structured cross-session handoff generation

- **Mechanism:** `oh-my-pi` generates structured handoff documents through a cache-aligned oneshot side request that shares the live prompt prefix, disables intentional tool dispatch (`toolChoice: "none"`, falling back to `"auto"` only if a provider rejects `"none"` while ignoring returned tool calls), checks context headroom before network I/O, validates required sections (such as a Goal section), and appends an exact inventory of read and modified files derived from observed tool operations.
- **Fit in Control Rod:** Control Rod runs agents as one-shot invocations (ADR 0020) rather than endless interactive threads. Generating a compact, validated handoff brief with an exact file-operation inventory between Author attempts—or when handing a card from Planner to Author—keeps context crisp, reduces re-reading cost, and gives human reviewers a plain-language summary of state.
- **Governance boundary:** Handoff briefs are strictly for human visibility and Author-lane continuity. A Blind Checker must **never** receive an Author's handoff narrative or reasoning summary; checkers inspect only the task contract and resulting artifacts/diffs to preserve blind cross-vendor independence.

### 4. Reversible secret obfuscation before provider egress

- **Mechanism:** Before text reaches a hosted provider, `oh-my-pi` scans environment variables with secret-like names, passwords embedded in connection URLs, built-in credential regexes (cloud, VCS, payment, bearer, and PEM formats), and global/project `secrets.yml` entries. In `obfuscate` mode, matches are replaced with deterministic HMAC-keyed placeholders (using a host-local private key never sent to models) carrying optional sanitized semantic labels and casing hints; live tool arguments are deep-walked to restore placeholders right before local tool execution. A one-way `replace` mode supports irreversible redaction.
- **Fit in Control Rod:** Adds a valuable defense-in-depth layer inside the daemon's egress path. Even when `AgentEnv` is stripped, repository fixtures, logs, or tool outputs can accidentally contain tokens; deterministic HMAC scrubbing prevents accidental exfiltration to hosted providers without breaking the model's ability to reference redacted handles in discussion.
- **Governance boundary:** Secret obfuscation complements—and never substitutes for—Control Rod's stripped `AgentEnv`, OS filesystem/network confinement, and host-CLI credential isolation (ADR 0021). Control Rod should default to one-way redaction for anything leaving the host to third-party providers, and never expose raw secret values or per-install HMAC keys in the web UI, API database, or signed audit records.

### 5. Phase handoff (`prewalk`) and two-tier blob/artifact storage

- **Mechanism:** `oh-my-pi` separates two complementary ideas for efficiency:
  - *Prewalk:* An optional one-shot handoff that lets a stronger model explore the repo and draft a plan, then automatically switches to a faster/cheaper implementation model at the turn boundary containing the first workspace write (optionally gated by a native classifier deciding whether the task benefits).
  - *Two-tier persistence:* Large binary payloads (such as images and frames) are externalized to a global content-addressed blob store (`blob:sha256:<hash>`) for deduplication, while truncated tool outputs and subagent logs spill to session-scoped monotonic files (`local://<N>.log`) written atomically via temp-file publish and exclusive claim.
- **Fit in Control Rod:** Two-tier blob and spill storage is a clean fit for Control Rod's run-artifact store, keeping JSONL run transcripts lightweight while preserving full tool output and visual evidence for review. The `prewalk` workflow mirrors Control Rod's Planner-to-Author progression: spend reasoning budget on the plan, then execute cleanly on a faster Author seat.
- **Governance boundary:** Under ADR 0022 and ADR 0023, Control Rod **forbids silent mid-run model switching** inside a single attested run. Prewalk-style handoff must happen only at an explicit, attested stage boundary (Planner card approval -> Author run dispatch), never invisibly mid-stream, and every seat's resolved model and vendor family remain attested on the run record.

### 6. Keyless local engine auto-discovery and on-device tiny-model workers

- **Mechanism:** `oh-my-pi` treats Ollama, LM Studio, and `llama.cpp` as implicit local engines discovered automatically via standard localhost URLs and environment overrides (`OLLAMA_BASE_URL`/`OLLAMA_HOST`, `LM_STUDIO_BASE_URL`, `LLAMA_CPP_BASE_URL`) with no API key required, while honoring explicit user configuration and `disabledProviders` before credentials. Separately, it runs lightweight on-device tiny models (ONNX Runtime / Apple Silicon MLX) in shared, idle-exiting local workers over Unix sockets for low-stakes tasks such as session titles and memory extraction.
- **Fit in Control Rod:** Keyless local discovery directly serves Control Rod's `Local-Only` preset and restricted/air-gapped data lanes—users running local engines get working seats on the Casting Desk without pasting dummy keys. Explicit `disabledProviders` precedence also provides a clean kill switch for project policy. Idle-exiting local tiny workers are a good pattern for non-governed convenience tasks (e.g., card title generation or log summarization) that should not burn cloud quota.
- **Governance boundary:** Discovered local endpoints must still pass daemon confinement and egress allowlisting (loopback-only for restricted lanes) and carry explicit locality and vendor-family attestation so a local model cannot masquerade as an independent cloud vendor in cross-vendor checking. On-device tiny-model workers must never be used for counted Author, Blind Checker, or policy-judgment verdicts.

## Not borrowed

- **Advisor / `WATCHDOG.yml` as a blind checker.** An in-run advisor reads the primary agent's live transcript delta and injects mid-run notes. Seeing author reasoning breaks blind independence and invites sycophancy. Control Rod's blind cross-vendor checker in `kernel/` remains untouched; if an advisor is ever offered, it stays strictly inside the author lane and never counts as an independent check.
- **`--tools`, `approvalMode`, or stream rules as a security boundary.** `oh-my-pi` itself notes that `--tools` is not an exclusive allowlist or confinement boundary. Control Rod never treats CLI flags, prompt-based approval modes, or stream regex rules as sandboxing; every runnable adapter is confined by Control Rod's OS sandbox, read-only checker mounts, stripped `AgentEnv`, and egress filter (ADR 0021).
- **Raw API key or token fields in the web UI.** Storing provider secrets in the browser or API database violates `docs/plan/HANDOFF.md` and ADR 0021. Sign-in stays with host CLIs or keyless local endpoints.
- **Fallback chains on Blind Checkers.** Rolling a failing or refusing checker over to another model enables pass shopping and weakens independence (ADR 0023, ADR 0024 Decision 6). Checkers hold on failure or quota exhaustion.
- **Unattested in-run subagent fan-out or silent mid-run `prewalk` swaps.** Silent subagents or invisible mid-run model switches break deliverable lineage attestation (ADR 0022, ADR 0023 Decision 5). Counted runs must disable hidden subagent spawning, keep phase handoffs at explicit stage boundaries, and record every observed model.
- **Passing author handoff narratives to Blind Checkers.** Structured handoff briefs help humans and subsequent Author turns, but feeding author reasoning into a checker compromises blind independence.
- **50-setting terminal/YAML config sprawl.** Exposing raw provider overrides, compatibility flags, and chains on the primary screen violates ADR 0024 Decision 3 ("Simple by default"). Advanced controls stay behind collapsed disclosures.
