# Plannotator: what to take, what to leave

> **Provenance.** Studied on 2026-11-16 at Plannotator commit `12974486d3aee98e265de588cf525876aff44fff` (github.com/backnotprop/plannotator). The repository is licensed "MIT OR Apache-2.0" (`LICENSE-MIT`, `LICENSE-APACHE`), so AGENTS rule 4 allows porting code with its notice kept. The clean-room roles in `README.md` are not required for a permissive source, and the reader did open the source. This file still carries ideas only: no Plannotator code, configuration or schema is copied. A short name in quotation marks is a Plannotator file or feature name. Paths below are relative to that commit. Some of its icon sets carry their own licenses (`packages/inbox/assets/icon-sets/*/LICENSE.md`); do not take assets without checking each one.

## Verdict

Plannotator is a local browser surface where a person reviews what coding agents produce: plans, documents, HTML and diffs. The person's notes go back to the agent as its next turn. Its product posture is the opposite of ours: its first agent rule is never to add gates, confirmations or owner-only checks that cost usability. Its engineering discipline is worth borrowing, though. It checks a lifecycle against a formal model, replays versioned traces across implementations, gives every test isolation a tripwire, and tests what agents do with their instructions.

## Leave alone

- **The usability-over-gates rule.** Plannotator deliberately avoids gates, confirmations and owner-only checks. Borrow its mechanisms, never its defaults.
- **Link sharing and hosted uploads.** Plans are shared as links, and larger ones are encrypted and uploaded to a hosted service. This does not fit owner-local work or the air-gap direction.
- **Two server runtimes that must change together,** and glue for ten agent harnesses. Our provider-neutral daemon is the right place for that breadth.
- **Hidden prompt text injected at session start and after compaction.** It is clever but hard to audit. In Control Rod, anything an agent is told goes into the run's recorded inputs.

## Worth knowing

- The repository is large and fast-moving. Port pieces at a pinned commit, with a PL7 provenance table; do not depend on it.
- Its Quint work does not run `quint verify`. The checks are random simulation and scripted traces, which is evidence of the absence of found violations, not a proof. Any Control Rod use of PL1 must say the same.
