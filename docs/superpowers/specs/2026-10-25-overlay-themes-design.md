# Interchangeable visual overlay themes: specification

Date: 2026-10-25. Status: approved for implementation by the user on 2026-10-26. See the execution ledger for observed implementation status; asset/public-release clearance remains separate.

Companions: [catalog](2026-10-25-overlay-themes-catalog.md), [implementation plan](../plans/2026-10-25-overlay-themes.md), [change basis](../../../.nuclear/changes/overlay-themes/basis.md).

## 1. Intent and decisions

Make Control-Rod's agent activity enjoyable and immediately legible through fifteen beautiful interchangeable worlds. Users should recognize the creative influences while seeing distinctive Control-Rod artwork. A theme is scenery, characters, props and choreography around real work; it cannot determine what work is accepted.

User direction: fifteen packs, characterful workers, strong cultural references, Monsters/Minion-influenced worlds first, Ocean's Eleven next, plus Wonka, Zelda, Friends and the expanded collection. No answer was given to the recurring-cast question. Proposed default: six unnamed supporting character variants per world with stable run badges; named recurring personalities are a later editorial choice.

### Approaches

| Approach | Benefit | Cost / decision |
|---|---|---|
| Palette and avatar swaps | Cheapest first result | Too little personality for the requested worlds |
| Shared renderer with declarative art packs | Reuses behavior while preserving distinct environments and cast | **Recommended planning assumption**, previously proposed in the conversation; not a claim of formal design approval |
| Independent miniature applications | Maximum freedom | Fifteen behavior/accessibility implementations; unnecessary divergence |

Build one renderer and one data projection. Packs are trusted bundled data/passive artwork, never executable plugins. Use React DOM, passive SVG image assets and CSS transforms/animations. No canvas/WebGL/game engine or new production dependency in the first release. Use existing React Query, TanStack Router, MSW and Vitest. Real browser verification can add a pinned permissively licensed development-only Playwright runner.

### Scope

V1 enhances `/floor`: theme gallery, scoped scene, shared actor model, task navigation, complete list for the selected package page, quiet/still controls, preferences, asset validation and fifteen art packs. Ship in waves after a three-pack engine pilot. The app header, Board, Office, evidence, decision controls and sign-in retain their current functional styling. No desktop-wide overlay, autonomous pet, game mechanics, sound, external pack installation, marketplace, user-uploaded SVG, recurring agent memory, or new agent/runtime behavior. No engineering values are generated by this feature. Numerical budgets below are proposed UI targets, not measured results or engineering outputs.

## 3. User experience

The Floor toolbar contains **Theme**, **Motion** (`Full`, `Quiet`, `Still`), and **View** (`Scene`, `List`), followed by package coverage and **Refresh**. Keep the existing app navigation. Theme gallery is a keyboard-operable modal with thumbnail, original title, one-sentence description, mood tags, availability and **Preview**/**Use theme**. The fifteen concepts may appear in a catalog, but only release-eligible packs have an enabled Use button. Unfinished or uncleared packs say **In development**. Plain Floor is always available and is not counted among the fifteen.

Preview is a static image or isolated static sample scene labeled **Preview — sample activity**. It never mounts live queries, sends metrics or affects selection/preferences until Use is pressed. Theme descriptions, attribution notes and availability are real product information; do not show internal validation flags or legal workflow fields.

Switching loads the proposed pack while retaining the current scene. On load failure keep the current pack, show a retryable message, and leave Plain Floor available. On success atomically replace artwork; keep page/filter, selected identity, live data, actor appearance assignments for that pack and focus. Persist only after successful activation. No document reload, query invalidation, mutation, progress replay or success celebration. Gallery closes and focus returns to Theme.

Actors are HTML buttons with package ID/revision, role, exact state text and a stable run badge. Hover and keyboard focus reveal the same short tooltip; Escape dismisses it. Long text is truncated visually with a full accessible label. Activate a run to navigate to `/packages/$id` and view details; an office item navigates to the existing `#decide` section. No drag/drop work assignment or embedded approve/stop controls. Opening a package is navigation, not a work mutation.

Scene and list use the same model. The list contains every projected entity in the selected page, including actors hidden by station capacity, and exact package/role/status text. Selection is tracked by entity ID; if it disappears, show “This activity is no longer in the current view” and return focus to the scene/list heading. Do not transfer selection to a different actor occupying the slot.

The gallery, toolbar and scene use normal text fonts. Decorative lettering stays in scenery and never replaces status, IDs or instructions. Scenes have coherent lighting, depth, silhouettes and thematic props; equivalent behavior is a requirement, identical-looking art is not.

## 4. Authoritative projection and freshness

### Query ownership and paging

`useFloorData()` owns `/packages`, `/office` and page-specific `api.packageView` queries. Default filter: Active (draft, released, in-work, in-verification). Optional All includes accepted/closed packages for inspection. Page size **30**; sort matching packages by canonical ID ascending, then slice. Previous/Next and “Packages 31–60 of 84 matching packages” are ordinary controls. Empty filter results say “No matching work packages.” A selected package is not silently pulled into a different page. Reset to the last valid page when the collection shrinks.

Fetch no more than **30** detail queries simultaneously. Selected-page details reuse `['views', id]`; office items match both selected package ID and revision. Counts from the full package list are labeled package counts, never worker totals. Office summary links to the full Office view. Missing details are not replaced by fake idle actors. Show “Loaded X of Y selected package details” while incomplete; errors list failed package IDs with Retry. Independent endpoint snapshots are not atomic: omit incompatible revisions and mark them **Updating**, then refetch; never combine newer package status with older run/acceptance data.

Reuse current SSE invalidation. While the Floor is visible, poll its active queries every **15 seconds** with no hidden-tab/background interval. Use query success timestamps, not render time. Mark a snapshot stale if any required source has failed or is more than **30 seconds** old; freeze work/carry/signature motion, retain last known labels, show **Updates unavailable — showing last known activity** and the oldest required successful timestamp. Required sources are package list, office and selected-page details; partial initial loads are Loading, not empty. On tab return refetch before restarting activity motion. Cached snapshots may render immediately with their stale designation. A successful response can remove an absent entity, but elapsed client time alone cannot turn a run into lost/failed/succeeded.

### Identity and entity kinds

- Worker ID `run:<run.id>`; task identity always includes package ID and revision. Cast variant is `fnv1a32(UTF8(run.id)) % 6`, unsigned, with a stored registry order. The same run has the same variant on rerender, reload and switching away/back. Different runs may share a variant; show distinct badges from the full run ID, do not imply six is a worker cap.
- Office item ID `office:<kind>:<package_id>:<package_revision>`; render as a **request marker**, not another agent. This avoids double-counting a run and its human request. Office requests never get a monster pretending to be the human approver.
- Package summary ID `package:<id>:<revision>`; a small card in archive/review, not an agent. It communicates accepted/closed or waiting-for-review state where appropriate. It does not imply we observed a submission event.
- Current queued/running runs are all included. For terminal runs retain only the latest per `(package revision, role)`, ordered by `finished_at ?? started_at ?? queued_at`, tie-break by run ID. Ignore runs for earlier revisions. This bounds historical clutter without hiding active rounds. Current terminal rows remain in the list; pagination bounds the package workload.
- Upstream duplicate run IDs collapse to one row; conflicting duplicates use an Unknown status with a data-warning message. Unknown future roles/statuses render neutral plain figures with raw text escaped, never drop the row or imply success.

### State mapping, in order

| Source condition | Exact visible label | Shared action | Station |
|---|---|---|---|
| Unknown/conflicting input | Status unavailable | idle | bench |
| `running` with `stop_requested_at` | Stopping | wait | run's work station |
| `queued` with nonempty `waiting_reason` | Waiting | attention | bench |
| `queued` | Queued | wait | bench |
| `running`, role `pre-check` | Pre-checking | inspect | verify |
| Other `running` | Working | work | role station |
| `succeeded`, role `pre-check` | Pre-check run finished | submitted | verify |
| Other `succeeded` | Run finished | submitted | role station |
| `failed` | Failed | error | role station |
| `lost` | Lost run | error | role station |
| `stopped` | Stopped | idle | bench |
| Office `permission` | Needs permission | attention | office |
| Office `lost` / `dispute` | Lost run / Dispute | attention | office |
| Office `accept` / `release` | Awaiting human review / Awaiting release | attention | office |
| Current package `accepted` | Accepted / Accepted with findings (when matching decision says so) | static archive seal | archive |
| Current package `closed` | Closed | static archive card | archive |

Source roles: intake and requirements-preparer → general; technical-preparer → site for capital-projects, otherwise general; author → site for capital-projects/site assignment, otherwise general; pre-check → verify. Bench overrides work location for queued/stopped. Human request markers occupy office. Archive maps the old doccontrol room. Theme station nicknames appear alongside these canonical meanings in tooltips/list.

`Run.succeeded` is not an output guarantee, passing check, verified work or acceptance. A matching `PackageView.pre_check.outcome` annotates **Pre-check passed** for `pass`, **Pre-check failed** for `fail`, or **Pre-check inconclusive** for `inconclusive` (the observed `VerificationRecord.outcome` union in `spec/records.tsp`). Map unknown future values neutrally. It never grants acceptance. Package acceptance uses the current package status; “Accepted with findings” requires a matching-revision decision of kind `accept-with-findings`. Without matching decision detail, display just Accepted. Revision mismatch suppresses acceptance decoration until refreshed.

V1 does not infer semantic states from free-text labels, runtime readiness, elapsed leases, dependencies or missing rows. `waiting_reason` is displayed as explanatory text, never parsed. A ready runtime is not proof a run is executing. `Input changed` is not inferred; existing package details remain the source for basis/integrity warnings.

## 5. Scene, animation and overflow

Use the existing **1000×600** logical stage, with six station bounds corresponding to current ROOMS. Pack artwork can suggest radically different worlds but must leave authored clear zones for general, site, verify, office, bench and archive. Each station has a fixed **three-column, two-row** slot grid; at most **six** interactive entities per station, **36** total. Inside office, request markers have their own slots; they do not displace workers in other stations. Sort by attention rank (lost/dispute, permission, awaiting review/release, failed, stopping, active, queued, terminal), then entity ID; stable order under reordered network arrays. Excess becomes a focusable **+N more** control opening the equivalent filtered list. The full list is never truncated. Do not move actors outside station bounds.

Container width below **960 CSS pixels** uses the list as the functional view with an optional static scenery thumbnail. Keep remembered Scene preference; restore it when width permits. Page/toolbar do not require horizontal scrolling at 320 pixels or 200% browser zoom. Actor controls have **44×44 CSS pixel** minimum hit areas. Decorations sit behind interactive entities with pointer events disabled. Tooltips avoid viewport clipping. Shared list/navigation remains accessible if graphics fail.

Shared actions: `idle`, `work`, `carry`, `wait`, `attention`, `inspect`, `submitted`, `error`. These are presentation names, not backend statuses. `carry` can occur only as a brief depiction of an observed same-run running→succeeded transition, never as random evidence delivery. Since package snapshots may skip states, a missing transition simply shows a static submitted pose.

- **Full:** subtle working/inspection loops, short bounded station transitions and one pack signature effect on observed submission. No autoplay audio, flashes, camera movement or fake numeric progress.
- **Quiet:** static positions; only a brief opacity/status emphasis on real state changes. No scenery loops or locomotion.
- **Still:** static poses and immediate state updates. OS reduced-motion forces Still even if Full is stored; user preference is preserved for when OS settings change.
- Hidden/offscreen/stale scenes pause all CSS motion and timers; update semantic text immediately. On return do not replay missed effects.
- Entry, refetch with unchanged state, pagination, theme change and reconnect do not replay submissions. Track previous `(entity ID, status)` only while a healthy live scene remains mounted; establish a baseline after data gaps. At most one signature effect per entity transition, maximum **1.2 seconds**. Animation completion never causes API calls or semantic state transitions.

## 6. Pack and asset contract

Version-1 pack descriptors are static TypeScript objects checked with `satisfies ThemePackV1` and build validation, lazy-loaded from a fixed allowlist. No dynamic import from strings supplied by a user, URL or API. Descriptor fields:

| Field | Contract |
|---|---|
| `schemaVersion` | literal `1`; incompatible versions are unavailable |
| `id`, `version` | catalog kebab-case ID; semantic version string, initially `0.1.0` |
| `title`, `description`, `moodTags` | original visible identity, plain text, no arbitrary HTML |
| `availability` | `development` or `released`; validation/rights gates further restrict release |
| `tokens` | `backdrop`, `surface`, `ink`, `mutedInk`, `accent`, `focus`; scoped to scene, never override StateMark/global decision colors |
| `assets` | `scene`, `thumbnail`, six ordered `characters`, and keyed props; each ref has local path, SHA-256, declared bytes, intrinsic width/height |
| `stations` | keys `general`, `site`, `verify`, `office`, `bench`, `archive`; decorative label and actor anchor geometry inside canonical bounds |
| `motionProfile` | literal `shared-v1`; `signature` from `none`, `capsule`, `spark`, `dossier`, `parcel`, `lantern`, `ripple` |
| `credits` | creator names, source/license notice IDs for shipped assets/fonts |
| `influenceNoteId` | optional pointer to a separately reviewed editorial note; never user HTML |
| `releaseRecordId` | checked provenance/release-manifest entry; not self-certified inside the art file |

Artwork is **passive local SVG**, referenced as image URLs with empty decorative alt text; status text is HTML. Never insert raw asset strings through `innerHTML`. Build validation rejects scripts, event attributes, foreignObject, external references, embedded remote fonts, animation elements and data URIs. Local fragment references for gradients/clips are allowed; a maintained XML parser must inspect elements/attributes, not a regex-only sanitizer. This is a repository asset gate, not a claim of supporting arbitrary untrusted SVG uploads.

Each pack delivers one 1000×600 scene, six character base silhouettes (128×128 viewBox with a common foot anchor), up to six reusable props (128×128), one static 800×480 thumbnail, token descriptor, source/credit manifest, and a review contact sheet. Shared CSS supplies eight action treatments; 192 hand-drawn frames per pack are not required. Artist may author optional static action overlays using the same six-prop allowance. No theme-specific JSX or custom motion code; if a pack needs a new primitive, add it to shared-v1 with tests or defer it.

Use system fonts for functional text. Original lettering embedded as artwork needs provenance like other assets. Do not import franchise logos, screenshots, character sheets, soundtrack clips, actor likenesses or copied dialogue as placeholders. Generative art can be a production tool, but records include tool, date, references, human edits and rights review; generation does not establish permission or exclusive ownership.

### Proposed loading/performance budgets

Selected pack artwork ≤ **1 MiB uncompressed**, thumbnail ≤ **100 KiB**, all fifteen thumbs ≤ **1.5 MiB**. Lazy-load only selected pack art plus visible gallery thumbs; do not preload fifteen scenes. Neutral app remains usable during load. Character motion uses transform/opacity with no React state update every frame. Maximum 36 animated actors as above. On the recorded reference machine, target p95 frame time ≤ **33 ms** over a 30-second full-motion fixture, selected cached theme switch ≤ **250 ms**, and network throttled cold activation ≤ **2 seconds** at 10 Mbps/100 ms RTT. Record machine/browser/viewport/build/cache and measurements; targets may require simpler art or Quiet mode, never hidden missing work. If the browser runner cannot measure a target reliably, record it unverified and keep the relevant release gate open.

## 7. Preferences, resilience and security

`FloorPreferencesV1 = {schemaVersion: 1, themeId: string, motion: 'full'|'quiet'|'still', view: 'scene'|'list'}` at localStorage key `cr.floor.preferences.v1`. Default theme Plain Floor, Full respecting OS, Scene respecting container width. This is an origin/browser convenience shared by local viewers, not an account setting. Store no package text, run ID, credentials or task data. Validate enums/shape; unknown versions reset; unavailable theme falls back to Plain Floor without deleting the remembered ID, so future compatible release can restore it. Malformed JSON, quota errors and blocked storage use in-memory preferences. Apply valid storage events from other tabs; ignore invalid ones. No reload or invalidation.

Theme error boundary resets on theme ID/version change, offers **Use Plain Floor**, and preserves list/navigation. Base queries live above it. Missing image changes that actor to the plain icon; missing scene falls back to a neutral background and announces a recoverable error. Never hide status behind a loader. A corrupt released descriptor is excluded by validation; a runtime load error cannot grant it availability.

Packs read display models only. Props must not receive the API client, auth objects, raw logs, document contents, signatures or evidence bytes. All text goes through React escaping. No outbound analytics, assets/CDNs, telemetry, generated copy service or runtime model call. No new wire fields, migrations or server mutations are needed. Existing APIs remain authority and the frontend is not a security boundary.

## 8. Influence, attribution and release posture

The user's preference is **recognizable creative influence**, not a prohibition on references. Keep explicit franchise names in internal briefs and allow proposed public factual influence notes. Original public names are a design choice, not a legal workaround. Mood/genre/ideas differ from protected particular expression; renaming copied characters is insufficient. “Inspired by,” credits, AI generation and an unofficial disclaimer do not themselves grant copyright/trademark permission. Referencing a name can be lawful depending on context and jurisdiction; this spec supplies no blanket legal determination.

Release data per pack records: asset hashes/creators; reference sources; rights basis (`original`, `licensed`, `public-domain` with verification); intended distribution; reviewed title/thumbnail/art/marketing; optional approved influence note text; attribution decision; reviewer/date/evidence reference; pack/version/hash binding. Public notes are optional, factual, subordinate to original identity, without franchise logos or official-endorsement language. Their exact placement and wording get the same review as artwork. Do not label all concepts approved merely because one pack is approved.

Engineering validation requires a complete release record for released packs; it checks records exist and match hashes, **not whether a legal conclusion is correct**. A designated human release owner accepts that record; exact franchise characters/assets or unresolved reference concerns require specific permission or qualified IP review before that pack ships. Other cleared packs continue independently. Proprietary licensed packs stay out of the Apache-distributed bundle unless the license explicitly permits that distribution; attribution does not relicense assets. The engine's source license and each asset license are recorded separately.

Primary U.S. guidance consulted for framing, not pack clearance:

- [Copyright Office: ideas versus expression and derivative rights](https://www.copyright.gov/what-is-copyright/)
- [Copyright Office: case-specific fair use](https://www.copyright.gov/fair-use/more-info.html)
- [USPTO: trademark source/sponsorship confusion](https://www.uspto.gov/page/about-trademark-infringement)
- [Dr. Seuss licensing, including Thing One/Two](https://www.drseussenterprises.com/licensing-and-collaborations)
- [Minecraft usage guidelines](https://www.minecraft.net/en-us/usage-guidelines)

## 10. Quality and accessibility acceptance

Target WCAG 2.2 AA for the new surfaces: functional text ≥4.5:1 contrast (large text ≥3:1), essential UI/focus graphics ≥3:1, no color-only state, visible unclipped focus, 44×44 targets as a product target. Test keyboard and screen reader in addition to automated checks. Dialog traps/restores focus, Escape closes, captions are readable at 200% zoom. Use a polite status region for snapshot/load errors and coalesced change counts, not a live announcement for every animation frame. The complete list is the primary screen-reader alternative; decorative scene art is hidden to assistive technology without hiding the real actor controls. Avoid duplicating tab stops by rendering only the selected functional view.

Browser matrix: current stable Chrome/Edge, Firefox and Safari desktop; mobile Safari/Chrome list fallback; record exact versions at execution time. Capture every pack with a shared fixture showing queued/working/pre-checking/waiting/failed/lost/stopping/review/accepted states, plus empty/loading/offline/overflow. Art review checks recognizable influence, original expression, lighting, silhouette diversity, clear functional regions and consistent quality. A passing screenshot test is not legal or accessibility clearance.

## 11. Rollout, completion and proposed defaults

Wave A: Creature Dispatch and Pocket Lab plus engine. Wave B: Midnight Bureau; stabilize the common primitives before increasing pack count. Wave C: Confectionery Works, Lanternwood Guild, Corner Café, Tumbletown Workshop. Wave D: Orbital Shipyard, Wildlight Research Camp, Voxel Foundry. Wave E: Cloudspring Bathhouse, Button & Spool, Clockwork Observatory, Coral Commons, Meadow Post. Fifteen is the target catalog, not a claim they can all ship in one engineering pass.

Use static Vite build configuration `VITE_FLOOR_THEMES_ENABLED` (default `false`) and a reviewed static release allowlist. `false` preserves legacy Floor/list behavior; preferences remain harmless. To roll back an individual pack remove it from allowlist and rebuild; its saved ID falls back gracefully. Assets use content hashes; a descriptor version change with modified bytes invalidates the prior release record. No server data rollback exists because the feature writes none.

Definition of implementation done: requirements/scenarios demonstrated; all fifteen packs reviewed or explicitly unavailable (the complete fifteen-pack release requires all fifteen available); observed relevant tests/typecheck/build; browser/accessibility/performance evidence on actual assets; source/asset provenance and distribution permissions; fallback/rollback rehearsal; no protected files changed without the applicable authorization. Planning completion means these documents and their review/check evidence exist, not that the product is built.

Decisions delegated to implementer: internal CSS class names, bounded slot padding inside the specified station geometry, pure helper decomposition, precise original character details within catalog constraints, and art tool choice with provenance. Planner defaults requiring review are listed in the basis; there is no unrecorded assumption that the user approved implementation, a recurring named cast, public franchise labels or legal clearance.
